# Holdout rule v11 and nuisance rule v4: the code the two versions require

## Context

Version 11 of `docs/holdout-rule.md` (commit `90b4bd9`) and version 4 of `docs/nuisance-rule.md` (commit `c9b8093`) are committed, their log entries pinned by `367e1e9`. Two campaigns follow them: the version 11 recalibration of the drawn targets (with the re-walk the version opens) and the version 4 re-admission of the nuisance servers. Both build their kits and dossiers from the repository (`run_holdout calibration-dossier`, `run_nuisance nuisance-dossier --readmission`), so the code the two versions require has to land before them. This plan writes that code. It transplants no recalibrated fixture, card or builder and merges no re-admission record: a separate plan does, once the campaigns end. Nothing in `src/mcp_auditor/` changes.

What the two versions ask of the code, clause by clause, with what the code does today (checked at `367e1e9`):

1. **The layout's owner.** Deployment layout: "Every target runs under an unprivileged account, uid and gid 65534, unless Proof has it run under the account named after a nonce. The layout, owned by the unprivileged account, is mounted read-only, or read-write on a target whose exploits, written from the published mechanism, write to it." Condition 2 of the layout now reads "with the same ownership on every target and the same mount mode on both versions of each target". Today `build_layout` and `build_empty_layout` (`evals/cve_layout.py` l.66 and l.78) build the tree on the host under a `tempfile.TemporaryDirectory()` (`_temp_root`, `evals/cve_environments.py` l.444 and its copy in `evals/holdout_kit/kit_launch.py` l.152), so the tree belongs to the host user (`_traversable_root` l.92 makes it 0755, the git calls run at umask 0o022). A server under 65534 reads it but cannot write to it, and git refuses a repository it does not own ("dubious ownership"). The module docstring of `cve_layout.py` still says the git and filesystem targets launch as the host user.
2. **The mount mode.** It is set by the builder, not by the target: `_git_launch` (`cve_environments.py` l.472, kit l.193) mounts `f"{root}:/srv"` read-write, every other builder `f"{root}:/srv:ro"`. Version 11 ties it to the target's exploits.
3. **The host uid.** `SymbolicUser.HOST` (`evals/cve_planting_base.py`) and `host_user_args()` (l.220) put the host's `os.getuid():os.getgid()` on the launch. Users today: the acceptance targets CVE-2025-53109 and CVE-2025-68143 (`_HOST_NO_NETWORK`, `evals/cve_targets.py` l.155, used l.237 and l.267), the holdout fixtures CVE-2025-11489, CVE-2026-4270 and CVE-2025-66335, the nuisance fix checks `evals/nuisance_fix_checks/cve_2026_4198_auto_commit.py` (l.38) and `cve_2025_53107_git_mcp.py` (l.32), which run git on the `/srv/app` checkout, and the run launch of two admitted nuisance servers (`"user": "host"` for auto-commit and git-mcp in `evals/nuisance_admission.json`, through `nuisance_confinement.user_args`). Two holdout-only builders bypass the planted user: `contextforge_ssrf_env` passes `--user 0:0` and `doris_db_env` passes none (the image runs as root).
4. **`/work`.** "A target that cannot write to the checkout, while a tool the flaw is reached through writes to the working directory before the flaw's code runs, takes as its working directory `/work`, an empty directory outside the layout that holds no place, and the checkout stays its scope." No such directory exists today. `PlantingHost.working_directory` is a free string (fixtures use `/`, `/tmp`, `/opt/server`, `/srv`, `/srv/app`).
5. **One class per target.** Proof (unchanged since version 10) files a target "under the union of its flaws' classes when they differ, or under no class when none fits". The code holds `mechanism: MechanismClass | None` on `CVETarget`, `KitTarget`, `PlantedTarget`, the grammar's `GradedTarget` protocol and `cve_oracle.TargetInfo`, and `_category_counts` (`evals/cve_grammar.py` l.280) reads one class. The recalibrated cards file several targets under a union, so the kit has to express one before the campaign writes those fixtures.
6. **The re-walk.** Versioning: "A new version takes a flaw the walk left out, other than a spent target, through the steps of Draw again only when it changes what that decision rested on, and its earlier give-ups then do not count. Such a flaw enters beside the drawn targets, even past the number the walk sought, and fills no vacancy." The log entry sends up to 23 flaws through Draw again and restarts the 15 excluded after two give-ups from a first calibration. Today `census_draw._walk_problems` refuses a flaw listed twice in the walk, `_calibration_problems` refuses a flaw with two give-ups and a card, `GiveUp.calibration` is `Literal[1, 2]` with no notion of which walk made it, and `_count_problems` (l.261) refuses more than 30 drawn targets. The committed draw record holds 86 walk steps, 30 drawn, 15 given up.
7. **Set-aside agents.** Census: "An agent is set aside with everything it wrote when a refusal on the fallback model or an interruption not directed at that agent cuts its session short, or when its output cannot be read. What it wrote counts neither as an attempt nor as a result, and the census records it with its cause." `census_work.AgentRecord` has `role`, `scope` and `model` only.
8. **The real software, and the card.** The real software runs "at the version the documentation names or else at the stable release that is current on the day of the calibration, which the card records with that release". `CalibrationCard` (`evals/census_draw.py`) has no field for it. Since version 11 changes a limit on what a fixture serves and the card, every drawn target's card is checked again (Versioning). `holdout_card_readiness.CARD_CHECK_RULE_VERSION = 9` and `run_holdout` refuses with "drawn targets whose card is not ready under holdout rule v9" (l.163).
9. **Nuisance, the release and the day.** "The admission records that release and that day, or those of the holdout card whose calibration it reuses." `AdmittedServer` has no such field. The fields a new version adds "are recorded for every admitted server by two admission agents" (Versioning), and `nuisance_unrecorded.refuse_unrecorded` refuses a run or a gate while "fields rule v3 adds are not yet recorded".
10. **Nuisance, the declared function per tool.** Admission: "for each tool of the flaw, whether its declared function is the effect of the flaw's class". The record is per flaw today (`FlawRecord.declared_function_is_effect`), and `nuisance_counting.flaw_counted_tools` drops every tool of a flaw marked true, which is why `adb_shell` of adb-mcp was taken off its flaw's tools.
11. **Nuisance, the raw count.** Each run "reports separately the part of that count that falls, in a category valid for the class of a counted flaw, on the tools of that flaw left out because their declared function is the effect of that class", computed in memory, in the run report only. `nuisance_counter.raw_fail_count` is the only raw count, carried per run in `NuisanceRunStatus.raw_fail_count` and printed by `nuisance_markdown._raw_fail_section`.
12. **Nuisance, the class at the admission.** The v4 log entry: "The servers the walk reached and left without an admission go through the admission, since only the admission sets a flaw's class under this rule." `nuisance_walk._sets_version` keeps a census flaw only when its class is graded, read from the census classifiers or from a `grammar_class` settlement of the draw or the walk record, and `nuisance_population` drops a server with no such flaw, so `run_nuisance walk` never lists it.
13. **The shared stand-in.** Both rules: a stand-in "chooses its answer only on fixed words at fixed positions of the request". Two AWS services the campaign serves under their real names answer every action on `POST /`: the query protocol names the action in the `Action` field of a form-encoded body (RDS), the JSON protocol in the `X-Amz-Target` header (Secrets Manager). The stand-in image (`evals/docker/Dockerfile.stand-in`) keys its routes on `(scheme, method, target)` in a dict, so two actions on one host collide and the last route wins silently. `StandInCapture` (`evals/public_stand_ins.py`) accepts two routes with one key. And a route is framed by its body's length only when its method is `GET` (`route['method']=='GET'` in `answer`), so a written `POST` route replays whatever `Content-Length` it carries.
14. **Rule line citations in the code.** `evals/cve_layout.py` l.79 and `evals/cve_environments.py` l.97 cite `holdout-rule.md:159`. Version 11 adds its sentence inside line 147 and a paragraph after line 202: line 159 is still "A server the layout breaks falls back to a pre-registered launch", so both citations stay true. No other `rule.md:NNN` citation sits in `evals/`, `tests/` or the living docs.

Fingerprints: `cve_baseline.ENVIRONMENT_PATHS` holds `cve_environments`, `cve_layout`, `cve_planting`, `cve_planting_base`, `cve_planting_spec`, `cve_planting_docker`, `public_stand_ins` among others, so every acceptance and holdout fixture fingerprint moves with this plan. `GRAMMAR_PATHS` holds `cve_grammar`. The counter fingerprint covers `nuisance_counter.py` and `nuisance_counting.py`. `evals/baselines/` holds no `cve/` and no `nuisance/` baseline, and no holdout run, nuisance run or gate run has taken place (both logs), so nothing is reset.

## Decisions

1. **The tree is built on the host, then handed to 65534 by a short-lived container.** The host user cannot `chown` without privilege, and the rule keeps the tree's nodes, contents and modes. So `build_layout` and `build_empty_layout` keep building it on the host (same git identity, dates, umask and modes, so it stays byte-for-byte universal), and once the tree is complete (the `leak<i>/report` links of `filesystem_env` included) and before the launch is yielded, a container runs `chown -hR 65534:65534 /srv` on it: `docker run --rm --label mcp-auditor-cve --user 0:0 --cap-drop ALL --cap-add CHOWN --security-opt no-new-privileges --network none --dns-search . -v <root>:/srv <helper> chown -hR 65534:65534 /srv`. `-h` is required: the leak links point at container paths absent from the helper. The owner is one constant for every target and both versions, as condition 2 asks. Rejected: a named volume (a copy step and a lifecycle that races a server container outliving stdin), a tmpfs with `uid=` (the server's own container would populate it, changing the launch the auditor is given), an idmapped mount (engine and kernel dependent), the planted account as owner (`ls -l` would print the nonce of `process-account-identity`).
2. **Removal goes through a container too.** The host user cannot delete entries inside 65534-owned directories, nor a 65534-owned directory under the sticky `/tmp`. So the layout root becomes `outer/srv`, `outer` a host-owned `TemporaryDirectory` with the prefix `mcp-auditor-layout-`, and teardown runs `docker run --rm --label mcp-auditor-cve --user 0:0 --cap-drop ALL --cap-add DAC_OVERRIDE --cap-add FOWNER --security-opt no-new-privileges --network none --dns-search . -v <outer>:/x <helper> rm -rf /x/srv`, best effort (it never raises and logs a warning, as the planting teardown does), before the `TemporaryDirectory` cleanup. Before that container runs, a one-line guard checks the path it is handed: a directory whose parent is the system temp directory (`tempfile.gettempdir()`, both resolved) and whose name starts with `LAYOUT_PREFIX = "mcp-auditor-layout-"`, else the removal refuses with `PlantingFailed`. The guard sits outside the best effort, since only a programming error reaches it (`owned_layout` always hands it the `outer` it made), and it keeps a root with `DAC_OVERRIDE` and `FOWNER` from running `rm -rf` on a broader host directory. A root with `DAC_OVERRIDE` and `FOWNER` removes whatever modes a read-write server left, a sticky directory included (`DAC_OVERRIDE` alone cannot unlink a 65534-owned file from a 65534-owned sticky directory). An orphan left by a crash is swept by prefix, documented beside the container and network sweep.
3. **The helper image is busybox pinned by digest**, the sentinel's base (`busybox:latest@sha256:fd8d9aa63ba2f0982b5304e1ee8d3b90a210bc1ffb5314d980eb6962f1a9715d`), a constant of `evals/cve_planting_docker.py`. It needs no compose build (the filesystem and git targets list no sentinel), works in the `mcp_auditor`-free calibration kit, and its digest sits in a fingerprinted module. Docker pulls it on first use, so the first launch needs network once.
4. **Through the existing port.** `PlantingDocker` gains `hand_over_layout(root: str) -> None` (raises `PlantingFailed`, a setup step) and `remove_layout(outer: str) -> None` (best effort past the guard of decision 2), implemented by `DockerPlanting` and by the stateful fake `tests/fakes/planting_docker.py`, so unit tests stay Docker-free. The context manager that owns `outer`, builds, hands over and removes lives once in `evals/cve_layout.py`, shared with the kit, and replaces both `_temp_root` copies.
5. **The mount mode is the target's, declared on its `PlantingHost`.** `PlantingHost` gains `layout_mount: LayoutMount = LayoutMount.READ_ONLY` (`READ_WRITE` otherwise). Every builder that mounts the layout reads `spec.host.layout_mount` through one helper in `cve_layout.py`, the git builder included, so no builder decides the mode any more. A target's two versions and its layout check share one host, so the mode is the same on both versions by construction. The host carries it because the builder signature `(image, spec, shape)` reaches the host through `spec.host` and nothing else, and `fixture_fingerprint` already hashes the host. `planting_host_parts` adds the mode only when it is `READ_WRITE`, as it adds the public names only when declared, so a read-only host (every nuisance host) keeps its parts.
6. **`/work` is a per-launch tmpfs the planting layer emits.** `cve_layout.WORK = "/work"`. When `spec.host.working_directory == WORK`, `planted` adds `--tmpfs /work:exec,mode=1777,uid=65534,gid=65534` to the launch's mounts. A tmpfs is empty at every launch, lies outside the layout, and needs nothing seeded in an image, so it is the same directory for every target that takes it. Owned by 65534 and writable by any account (sticky, as `/tmp`), so a target under the account named after a nonce can write to it while `ls -ld /work` prints `nobody`, never the nonce. `exec` keeps it an ordinary directory. `planting_spec` refuses a file place that resolves under `/work` (a relative coordinate resolves against the working directory), since `/work` holds no place.
7. **The host uid leaves what this plan owns, and the kit refuses any other account.** CVE-2025-53109 takes `_UNPRIVILEGED_NO_NETWORK`, CVE-2025-68143 `PlantingHost(SymbolicUser.UNPRIVILEGED, "/", has_network=False, layout_mount=LayoutMount.READ_WRITE)` (its `git_init` exploit writes a `.git` into `/srv`, now writable by its own account), and `_HOST_NO_NETWORK` goes. The two git fix checks take `SymbolicUser.UNPRIVILEGED`: under the host uid, git would refuse the 65534-owned checkout. The calibration kit's `check_target` reports, as a dead condition, a launch whose `--user` is anything but `65534:65534` or the planted account's `uid:gid`, or that sets none: a builder the agent writes can bypass the planted user (as `contextforge_ssrf_env` does), so the check reads the yielded argv, not the host. It reads every spelling Docker accepts (`--user <v>`, `--user=<v>`, `-u <v>`, `-u=<v>`, `-u<v>`), so a launch that runs as 65534 is never reported as setting none. It reads only the Docker options before the image (`image_tag(service)`, which `_exercise` knows), since a server argument after the image may spell `-u` or `--user` for its own purpose. `SymbolicUser.HOST` and `host_user_args` stay until the three holdout fixtures, the two holdout-only builders and the two nuisance run hosts that still use them are rewritten (What stays unchanged).
8. **A target carries a set of classes.** `mechanisms: frozenset[MechanismClass]` replaces `mechanism` on `CVETarget`, `KitTarget`, `PlantedTarget`, `GradedTarget` and `TargetInfo`. The empty set is "no class", the only spelling of it. `_category_counts` counts every category under the empty set and otherwise a category any class of the set admits. `VALID_CATEGORIES` and `MechanismClass` do not change. `FixCheckTarget.mechanism` stays one class or `None` (`MechanismClass | None`, one nuisance flaw, matched against the admission's per-flaw `effect_class`) and becomes the empty set for `None`, else a one-element set, where it builds its `PlantedTarget`. Every existing target is re-encoded mechanically to its one class: no grade moves, which the grammar golden master, unregenerated, proves byte for byte. The fixture fingerprint encodes the class part as before for zero or one class (`None`, or the class value) and as the sorted list of values for several, so this change moves no fixture fingerprint, only the grammar fingerprint. `evals/nuisance_admission.json` gets the new `grammar_fingerprint` in the same commit (its loader refuses a stale one), and nothing else in that file. `CalibrationCard.effect_class` stays a free string.
9. **The draw record tags each walk step and each give-up with the rule version that decided it.** `DrawWalkStep.rule_version: int | None = None` and `GiveUp.rule_version: int | None = None`, `None` for what was decided before the first re-walk, as `CardCheck.rule_version` already reads. A flaw is listed at most once per version, and its step under the latest version governs. Give-ups count within the version that made them, so earlier ones "do not count". `_count_problems` goes: the rule lets a re-walked flaw enter past the number the walk sought, and no other number bounds the drawn list. The re-walk itself (which flaws a version sends through Draw again, the order, a flaw that waits for an earlier flaw of its server) stays the maintainer's act, recorded in the census: no code decides it. A separate list of re-walks was rejected: the steps would be split across two lists that every reader of the walk would have to merge.
10. **A set-aside agent is an `AgentRecord` with its cause.** `AgentRecord.set_aside: str | None = None`. A set-aside calibrator or card-checker record does not satisfy `_agent_problems`, since what it wrote counts as no attempt.
11. **The release and the day are one shared record.** `evals/fixture_provenance.py` gains `SoftwareRelease(software: str, release: str, day: date | None, source: str)`: the software as its documentation names it, the release it runs, the day that release was the current stable one (`None` when the documentation names the version), and the line of documentation or the release page that gives it. `CalibrationCard.software_releases: list[SoftwareRelease] | None = None` and `AdmittedServer.software_releases: list[SoftwareRelease] | None = None`, `None` reading "not yet recorded", `[]` "no real software". A twin copies its holdout card's list.
12. **The card check moves to version 11.** `CARD_CHECK_RULE_VERSION = 11`, the readiness requires `software_releases`, and `run_holdout run` refuses with "drawn targets whose card is not ready under holdout rule v11". Every committed card check reads `rule_version: null`, so the refusal changes no outcome today.
13. **The declared function is recorded per tool, and the counter keeps reading the flaw's record** (Settled decision 1). `ToolRecord.declared_function_is_effect: bool | None = None` is recorded for the re-admission. `flaw_counted_tools`, `counted_tools` and the counter do not read it in this plan, so the counted tools, the nuisance fixture fingerprints and the counter fingerprint do not move with it. The counter's per-tool reading lands with the deferred rework, and the flaw-level field stays until then.
14. **The v4 fields join the run's refusal.** `nuisance_unrecorded` lists, per audited server, `software_releases` when `None`, `declared_function_is_effect (n tools)` for every non-removed tool of a counted flaw whose record is `None`, the tools left out by their declared function included, and `holdout_fingerprint (n flaws)` for every counted flaw whose `fix_check.source` is `holdout_calibration` and whose `holdout_fingerprint` is `None` (decision 18). The run and the gate refuse with "fields rule v3 or v4 adds are not yet recorded", the vet counts them. Every admitted server lacks them until the re-admission, which is expected: no run precedes it.
15. **The split of the raw count.** `nuisance_counting.declared_function_tools(server) -> dict[str, frozenset[JudgeCategory]]`: for each counted flaw with a class whose `FlawRecord.declared_function_is_effect` is true (the record the counter reads, decision 13), the tools that record alone leaves out, that is the tools `flaw_counted_tools` would keep were the record false (not removed, the flaw's backend not `external`, real software that answers), with the categories valid for that class, unioned per tool. `nuisance_counter.fail_count_on(report, tools) -> int` counts the FAIL verdicts on those tools in their categories. `NuisanceRunStatus` gains `declared_function_fail_count`, the report line `declared_function_fail_per_run`, and the Markdown raw-count section prints it beside the raw count. In memory, from the report the run already holds, and in the nuisance run report only: the gate report does not carry it.
16. **The nuisance walk leaves the class to the admission.** `_sets_version` stops reading the class (the classifiers' `effect_class` and any `grammar_class` settlement). It keeps the other census readings the rule does not hand to the admission: the tool reach, the effect in a tool response, the pinnable versions. A server whose census flaws are all outside the grammar is then listed by `run_nuisance walk` and goes through the admission. Its docstring and the printed label say the version-setting flaws are pending the admission's class.
17. **The stand-in branches on the AWS action.** `StandInRoute` gains `action: str | None = None`, allowed only on a `POST` route. The image reads, for a request, the action as the `X-Amz-Target` header's value when present, else the `Action` field of an `application/x-www-form-urlencoded` body (the media type compared without its parameters, since botocore sends `application/x-www-form-urlencoded; charset=utf-8`), else none, and answers the route keyed `(scheme, method, target, action)`, then the action-less route of `(scheme, method, target)`, then for a `HEAD` the `GET` route, then the scheme's default. Reading the action needs the body, so the handler reads `Content-Length` bytes of a request that carries one. Both are fixed words at fixed positions of the request, as the rules ask, and an unknown action gets the default, as the real service answers an action it does not know with an error. Every route but a captured `HEAD` route is framed by the length of the body it serves (`route['method']!='HEAD'`), so a written `POST` route needs no hand-computed length. `StandInCapture` refuses two routes with one `(scheme, method, target, action)`. A URL given twice to `capture_stand_in` is caught by that refusal when the capture loads, so the capture command itself does not change. The capture command records no action: the AWS routes are written from the services' published examples, since a real capture would need signed requests. The two protocols spell the action differently, and the module docstring of `evals/public_stand_ins.py` says so: a JSON-protocol route keys on the full `X-Amz-Target` value (for example `secretsmanager.GetSecretValue`), a query-protocol route on the bare `Action` value (for example `DescribeDBInstances`).
18. **A copied holdout calibration carries the fingerprint it was copied at** (Settled decision 2). `FixCheckRecord.holdout_fingerprint: str | None = None`: for a record whose `source` is `holdout_calibration`, the `cve_baseline.fixture_fingerprint` of the holdout target it copies, recorded by the maintainer at the merge, `None` reading "not yet recorded" (decision 14). A record whose `source` is `fix_check` carrying one is a load problem. A pure `nuisance_holdout_copies.stale_holdout_copies(servers, current: Mapping[str, str]) -> list[str]` reads, for every counted flaw of an audited server whose record copies a holdout calibration and carries a fingerprint, whether its flaw is a key of `current` (the drawn targets' identifiers mapped to their current fixture fingerprints) and whether the fingerprint is equal, and lists each copy whose target left `HOLDOUT_TARGETS` or whose fingerprint differs. `run_nuisance run` builds `current` from `HOLDOUT_TARGETS` and `load_places(HOLDOUT_PLACES)` and refuses (exit 3) on a non-empty list, after `refuse_unrecorded` and before any LLM or Docker work. The gate does not read it: an acceptance server gives no holdout target, so it copies no holdout calibration. The field stays out of the nuisance fixture fingerprint, as every fix-check record does, and out of the kit's `FixCheckResult`, which the kit cannot observe.

## Approach

Nine commits, one concept each, tests first in each. The order serves the campaigns: the calibration kit needs commits 1, 2, 3, 5 and 9, the re-admission dossier needs 6, and 4, 7 and 8 complete what the two versions ask before the census is updated and before any run. The step breakdown may merge or reorder them. Fingerprints are printed before the first commit and after each commit that moves them.

1. A target carries a set of classes (decision 8).
2. The layout belongs to the unprivileged account, and the host uid leaves the acceptance targets and the two git fix checks (decisions 1 to 4 and 7, the kit guard aside).
3. The mount mode is the target's, `/work`, and the kit refuses any account but 65534 or the planted one (decisions 5 to 7).
4. The draw record carries the re-walk and the set-aside agents (decisions 9 and 10).
5. The card records the real software's release and is checked under version 11 (decisions 11 and 12).
6. The admission records the release, the per-tool declared function and the fingerprint of a copied holdout calibration, and the run refuses them unrecorded or stale (decisions 11, 13, 14 and 18).
7. The nuisance run reports the raw count on the tools left out by their declared function (decision 15).
8. The nuisance walk leaves the class to the admission (decision 16).
9. The stand-in branches on the AWS action and refuses duplicate routes (decision 17).

Each commit carries its living docs and its log entries, written in the commit they record from the fingerprint lists the step produces (see Logs).

## Edge cases

- A hand-over that fails (the busybox pull fails offline, Docker refuses, or the chown stops midway) raises `PlantingFailed` before the yield, after `remove_layout` and the cleanup of `outer`: the runner maps it to a skipped run, as a planting failure.
- A body that raises inside the builder: `remove_layout` runs, then the `TemporaryDirectory` cleanup, and nothing stays under the host's temp directory. A removal that fails logs a warning and leaves the `mcp-auditor-layout-*` directory to the sweep, never raising out of `__exit__`.
- A read-write server that leaves a directory at mode 0500, a sticky directory (mode 1777) holding its files, or a file it created as 65534: the removal container's `DAC_OVERRIDE` and `FOWNER` remove it. The integration test of the sticky directory guards `FOWNER`.
- A removal handed a path that is not a directory under the system temp directory with the `mcp-auditor-layout-` prefix (an empty string, `/`, the temp directory itself, a nested path): `check_layout_outer` refuses with `PlantingFailed` before any container runs.
- A host running rootless Docker, `userns-remap` or Docker Desktop: the chown fails, the hand-over raises `PlantingFailed`, and every layout target is a skipped run. The kit's README says rootful Docker on Linux is required.
- The leak links of `filesystem_env` point at container paths absent from the helper: `chown -h` changes the link, never follows it.
- A target under the account named after a nonce (uid 60123) reads the 65534-owned tree as "other" (0755 and 0644) and cannot write to it, read-write mount or not: such a target that must write before its flaw takes `/work`, which it can write to.
- A target whose working directory is `/work` loses the `$WORKSPACE/.env` route that walks up from the working directory: a calibration consequence, not a code one.
- A file place with a relative coordinate on a `/work` host resolves under `/work`: refused by `planting_spec`.
- The empty-layout arm of the layout check is handed over the same way and mounted with the target's mode, so both arms differ only by their nodes.
- Concurrent launches each own their `outer` directory, so `run_holdout calibrate --concurrency` and the fix checks never share a tree.
- A holdout target under 65534 that runs git in the checkout: git refused the host-owned checkout before, and accepts the 65534-owned one now, so an exploit or a benign call may answer differently. `run_holdout calibrate` and `run_nuisance calibrate` before and after show it: any changed verdict is reported to the maintainer, never adjusted here.
- A flaw re-walked under version 11 that gives up twice again: two give-ups under version 11 and a `given_up` step under version 11, its two earlier give-ups left in the record and not counted.
- A drawn target that a version takes out (no longer eligible): its governing step is no longer `drawn`, so it must leave `drawn`. Its card stays in the record as history (a card still needs some `drawn` step).
- A tool that two counted flaws reach, counted through one and left out by its declared function through the other: it is in both maps, the split counts its FAILs in the categories of the flaw that leaves it out, whatever else counts them. The split is a part of the raw count, never of the figure.
- A server whose every tool is left out by its declared function is not audited, so it has no split count.
- A twin whose holdout target goes back to calibration: once the recalibrated fixture is transplanted, its fingerprint differs from the recorded one and the run refuses until the admission copies the calibration again. While no `holdout_fingerprint` is recorded (every twin today), the run refuses it as unrecorded instead.
- A server launch argument after the image that reads `-u` (a database user, say) does not satisfy or fail the kit's account check, which reads only the options before the image.
- A request with an action to a host whose routes carry none (a non-AWS `POST`) still gets its action-less route. An AWS request whose action no route names gets the scheme's default.
- A captured `HEAD` route keeps its captured `Content-Length`, as pinned by `b1c0b99`. A `HEAD` falling back to a `GET` route is framed by that body.
