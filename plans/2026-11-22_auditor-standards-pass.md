# Standards pass on the auditor

## Context

The auditor (`src/mcp_auditor`), its unit tests (`tests/unit/auditor`), its fakes (`tests/fakes/llm.py`, `tests/fakes/mcp_client.py`, `tests/fakes/chat_model.py`, `tests/fakes/__init__.py`) and its integration tests (the MCP client, confined launch, relayed environment, resume and honeypot tests of `tests/integration/`) were reviewed against the coding, testing and architecture standards of `CLAUDE.md`. A mechanical inventory listed the functions over 20 body lines, over 3 arguments and the files over 300 lines. Twenty reviewers then read the code, sixteen file by file and four across the whole area (architecture and boundaries, duplication and missing concepts, ubiquitous language, the tests as a whole). Nine more verified each finding against the code, rejected those that did not hold or traded one standard for another, merged the duplicates, and designed the fix of the rest. This plan carries the 61 fixes that survived. None is a high-priority defect: the area already holds to its standards, and what is left is knowledge written in several places, words outside the glossary, a few missing concepts and test support that copies itself.

## Approach

Each fix below is small and stands on its own, except where the order notes of its section say otherwise. They are grouped in nine sections, in the order they are implemented: packages, providers and configuration first, since emptying the package facades changes import lines everywhere, then the LLM adapter, the audit and CLI, the launch and server watch, the domain models, the graph nodes, the prompts and rendering, and the test support last, since it moves builders the earlier sections only import. Within a section, the fixes are listed in the order the section's notes give. A reference such as "fix 5.4" names a fix of this plan.

## Decisions

- Two fixes change behavior, and each lands in its own commit: fix 7.7 (the Markdown summary counts attack chains on their own line instead of adding them to the test cases, with a `CHANGELOG.md` line under `[Unreleased]`) and fix 4.4 (a declared container's short `docker run` options, such as `-e` or `-v`, no longer raise a false warning, the two argv readings merged into `domain/container_name.py`). Fix 1.3 also rewords the unknown-provider error, which lists the accepted providers from their registry, with a `CHANGELOG.md` line under `[Unreleased]` `### Changed`. Every other fix is a refactoring and keeps behavior.
- The import and name rewrites a fix causes outside the auditor (in `evals/`, `tests/unit/cve`, `tests/unit/detection`, `tests/unit/nuisance`, `tests/unit/evals`, `tests/unit/support`, `tests/integration/support`) land in the same commit as the fix: emptying `domain/__init__.py` (fix 1.2), splitting `domain/models.py` (fix 5.5), renaming `MissCause` (fix 5.6) and `UnparseableOutput` (fix 5.7), moving `SendAttempt` (fix 4.1). No module an eval fingerprint hashes imports a name these fixes rename or move (checked against the fingerprinted sources: `GRAMMAR_PATHS` and `ENVIRONMENT_PATHS` of `evals/cve/detection/baseline.py`, `_COUNTER_PATHS` of `evals/cve/nuisance/counter.py`, `CONFINEMENT_SOURCE` and `PUBLIC_NAME_SOURCES` of `evals/cve/nuisance/fingerprint.py`, the files the backends serve and the targets' `backend_sources`), so no fingerprint moves.
- A rename that changes the vocabulary of an identifier gets its `docs/glossary-log.md` line in the same commit when the old name appears in an ADR or a plan, as `AuditStep` and `MissClass` did: fix 3.3 (`AuditRunOptions(budget=..., chains=...)`, cited by plans/2026-11-21_tests-review-since-new-tests-review.md), fix 2.7 (`host` for an OpenRouter provider, cited by plans/2026-10-15_openrouter-provider.md), fix 4.2 (`WatchStep`, cited by plans/2026-11-16_relaunch-stopped-server.md), fix 5.6, fix 5.7 and fix 7.1 (`marker(name)`, cited by plans/2026-10-03_relayed-environment.md and plans/2026-10-20_test-suite-review.md).

## What stays unchanged

- Every prompt and every structured-output schema sent to a model: `graph/prompts.py` and `graph/chain_prompts.py` may be refactored, but their output stays byte-identical, and `tests/unit/auditor/test_model_inputs_golden.py` passes without regenerating its golden. A red golden means the fix is wrong: revert it, never regenerate.
- `compute_thread_id` and the pinned unconfined hash.
- The CLI flags, the `--help` text, the config-file keys, the JSON report's field names and values, the LangSmith metadata key `budget`, the checkpoint location `~/.mcp-auditor/checkpoints.db`. The Markdown report changes only through fix 7.7.
- Every module an eval fingerprint hashes, the three honeypots (`tests/honeypot_server.py`, `tests/subtle_server.py`, `tests/chain_honeypot_server.py`), the Dockerfiles and stand-in captures, `docs/adr/` and `plans/`.
- Names sent to the model (`TestCaseBatch.cases`, `EvalVerdict`, schema fields).
- `tests/unit/project/support/code_standards_debt.py`: no entry is added. The newspaper rule, the one given/then pair per test file and the absence of `monkeypatch.setattr` hold on every file this plan writes.

## Edge cases

- Emptying a package `__init__.py` can surface a circular import that its eager imports masked: the full test run catches it, and the fix is to import from the defining module, never to restore the facade.
- A rename that misses one reference fails `uv run pyrefly check`, which is the completeness check of every rename here.
- `tests/unit/auditor/support/graph_builders.py` feeds the model-inputs golden and `tests/integration/support/unconfined_audit.py`: a fix may add a builder there, never change an existing default.
- A moved test keeps its assertions: moving it is not a reason to rewrite it.

## Verification

After each fix: the test files it touches with `uv run pytest <files> -n 0`, then the short loop `uv run pytest tests/unit -n auto --maxprocesses 6`, `uv run ruff check .`, `uv run ruff format .` and `uv run pyrefly check`. A fix that touches committed content or an integration test runs those files too (`tests/integration/test_confined_launch.py`, `tests/integration/test_mcp_client*.py` and `tests/integration/test_honeypot_server.py` for section 4, the four integration files of fix 3.2 for section 3, `tests/integration/test_relayed_environment.py` for fix 7.1). A fix that edits committed content (`CHANGELOG.md` for fixes 1.3, 4.4 and 7.7, `docs/glossary-log.md` for fixes 3.3, 4.2, 5.6, 5.7 and 7.1) also runs `uv run pytest tests/integration/committed -n auto`, which holds the glossary tests. Each section closes with `uv run pytest -n auto`. `tests/unit/auditor/test_model_inputs_golden.py` and `tests/unit/project/test_code_standards.py` pass at every step without regeneration or new debt.
