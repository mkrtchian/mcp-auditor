# Eval harness fixes: a traversable layout root, neutral backend names, no host search domain, the stand-in's default answer

## Context

The card checks of the holdout v9 recalibration campaign reported four harness defects that no fixture can repair on its own: the `/srv` layout root that an unprivileged server cannot traverse (transverse findings T1 and T8), backend hostnames that name the audit (T2, gap 2 of CVE-2025-66335), the host's DNS search domain copied into every fixture container (T2, CVE-2026-58485), and a stand-in that answers an empty 404 to any request its capture lacks (T3). This plan repairs the harness for the three Docker suites (CVE acceptance, CVE holdout, nuisance). It repairs no fixture: the workarounds the fixtures took against these defects are calibration work, done by the calibration and admission agents afterwards. Nothing in `src/mcp_auditor/` changes.

What the code does today, checked at `b6785fc`:

1. **The layout root is 0700.** `evals/cve_layout.py` `build_layout(root, nodes)` (l.64) and `build_empty_layout(root)` (l.75, `root.mkdir` l.84) never set the root's mode. The root is a `tempfile.TemporaryDirectory()` (`mkdtemp`, mode 0700, owned by the host user) in `evals/cve_environments.py` `_temp_root` (l.445) and in `evals/holdout_kit/kit_launch.py` `_temp_root` (l.152), mounted at `/srv`. Docker is rootful here without userns-remap, so the container sees 0700 owned by uid 1001, and `confinement_args` drops `CAP_DAC_OVERRIDE`. Under `SymbolicUser.UNPRIVILEGED` (`--user 65534:65534`) a server cannot resolve an absolute path under `/srv` nor go up with `..`: `ls /srv`, `cat /srv/.env`, `cat ../.env` from `-w /srv/app` all fail with `Permission denied`, and biome dies at start with `spawn .../esbuild EACCES` from `-w /srv/app` under 0700 and answers under 0755 (`~/holdout-calibration/v9/review/layout_permission_check.md`, measured on `b6785fc`). Consequences: the layout check (`evals/cve_layout_check.py`) compares two arms built under the same 0700 root, so a break the root causes shows on both and the fallback never fires; the leak guard is blind for an unprivileged server, which cannot read the layout at start; a layout place kept for an unprivileged target would read dead. Today no unprivileged target keeps a layout place (the only one, CVE-2026-4270, runs as the host user). Fixtures worked around it: CVE-2026-3680 moved its working directory to `/opt/server` (fixture comment l.30), CVE-2026-5603 to `/tmp` (l.89), CVE-2026-5323 to `/tmp` (l.59, a case the review does not list), and CVE-2026-4270, CVE-2025-11489 and CVE-2025-66335 run as the host user. Inside the root, `build_layout` creates `app` and `app.git` at 0775 and `.env` at 0664: the modes follow the host's umask (0002 on this host), through `_git` (l.127, a plain `subprocess.run`) and `Path.write_text`.
2. **Backend hostnames that reach a server name the audit.** `evals/doris_backend.py` names the cluster `DORIS_CONTAINER = "mcp-auditor-cve-doris"` (l.47), starts it with `--hostname DORIS_CONTAINER` (l.103), and the server reaches it by that name: `DORIS_SERVER_LAUNCH` (l.55) passes `--db-host DORIS_CONTAINER`, which `get_adbc_connection_info` returns (card check of CVE-2025-66335, gap 2). The same value sits in the admission's doris `launch` (`evals/nuisance_admission.json` l.1281) and in the holdout launch `cve_environments.doris_db_env` (l.428 to 429, the literal twin of `doris_server_args`). `evals/mysql_backend.py` names `MYSQL_CONTAINER = "mcp-auditor-cve-mysql"` (l.40), `MOTO_CONTAINER = "mcp-auditor-cve-mysql-moto"` (l.41) and `MOTO_ENDPOINT = f"http://{MOTO_CONTAINER}:5000"` (l.42), reached by container name: `evals/docker/Dockerfile.mysql` l.12 `ENV AWS_ENDPOINT_URL=http://mcp-auditor-cve-mysql-moto:5000`, and the mysql benign call's `db_endpoint` is `"mcp-auditor-cve-mysql"` (admission l.3943). `evals/neo4j_backend.py` names `NEO4J_CONTAINER = "mcp-auditor-cve-neo4j"` (l.35), reached through `evals/docker/Dockerfile.neo4j` l.9 `ENV NEO4J_URI=bolt://mcp-auditor-cve-neo4j:7687`; `Dockerfile.neo4j-vuln` l.9 carries the same `ENV`, which the fix check `cve_2026_35402_neo4j_cypher` overrides with `-e NEO4J_URI=bolt://neo4j-db:7687` on its own bridge. The ten responders are reached at fixed addresses with `--add-host` pins of public names, so their container names reach no server through name resolution. A grep of `mcp-auditor`, `mcpaudit` and `cve` over the launches, environments and run Dockerfiles of the admitted servers and over the admission's launches and benign-call arguments finds no other backend name. It finds values of another kind, out of this plan's scope (What stays unchanged): the layout's neutral token `mcpaudit-placeholder` (`cve_layout.NEUTRAL_TOKEN` l.30) and its git identity `mcp-auditor <bench@mcp-auditor.local>` (l.54 to 61), in files a server can read; the nonces `MCPAUDIT-<hex>` and the account `mcpaudit-<hex>` (`cve_planting_base._RandomNonces`); the `<segment>` placeholder `mcpaudit-placeholder` of `cve_planting_spec` (l.37), which no committed place coordinate uses; and fixture words the rules forbid (`calib-token` in the apify, atlassian and gitlab server environments, `# cve-rebind` in the contextforge images' `/etc/hosts`, and `benign`, `stub`, `seed` or `calib` in the flyto, android, markdownify, n8n, vibe-trading, scrapling, geekgod-fs and git-mcp fixtures).
3. **Names that do not reach the server through the launch, measured from inside a target.** Image names, labels, holder, sentinel, stand-in and network names never appear in a target's argv, environment, hostname (Docker's default is the container id), `/etc/hosts` or `/etc/resolv.conf`. They do appear through Docker's embedded DNS: a reverse lookup of a container's address on a user-defined network answers `<container name>.<network name>`, and a network alias does not change that answer (measured on Docker 29.9.2, 2026-11-03: a container named `X` with `--network-alias doris` reverse-resolves to `X.<network>`; a target joining a holder reverse-resolves its own address to `<holder>.<network>`). So a server that reverse-resolves its own address or a backend's reads `mcp-auditor-cve-<hex>.mcp-auditor-cve-<hex>`, `mcp-auditor-cve-<key>-server-<uuid>.mcp-auditor-cve-<key>-bridge` or `mcp-auditor-cve-doris.mcp-auditor-cve-doris-bridge`.
4. **`/etc/resolv.conf` copies the host's values.** Measured on this host on 2026-11-03 with throwaway busybox containers (host `/etc/resolv.conf`: `nameserver 127.0.0.53`, `options edns0 trust-ad`, `search <host domain>`): on a closed network the file holds `nameserver 127.0.0.11`, `search <host domain>`, `options edns0 trust-ad ndots:0` and the comments `# Based on host file: '/etc/resolv.conf' (internal resolver)` and `# ExtServers: [host(127.0.0.53)]`; under `--network none` it holds `nameserver <LAN resolver>` twice (the LAN's resolver, from `/run/systemd/resolve/resolv.conf`), `search <host domain>` and `# Based on host file: '/run/systemd/resolve/resolv.conf' (legacy)`. `--dns-search .` removes the `search` line in both cases (`# Overrides: [search]`) and nothing else. A container started with `--network container:<holder>` reads the holder's file: Docker accepts `--dns-search` and `--dns-option` on it but they have no effect (a joiner of a holder started without the option still reads `search <host domain>`), and Docker refuses `--dns` there (`conflicting options: dns and the network mode`). Every fixture container that joins a holder (the target, the stand-ins, the bound sentinels, the address setups, the probes) therefore takes the holder's file. `cve_planting_base.confinement_args()` (l.190) is the one helper every fixture container of the three suites takes, the holder (`cve_planting._holder_args` l.198), the sentinels (l.224), the stand-ins (`cve_planting_stand_ins.serve_stand_ins`), the address setups, the probes (`_probe_endpoints` l.146), the 13 server launches of `cve_environments`, the kit launches, the nuisance launches through `nuisance_confinement_args()`, the responder singletons (`Responder.singleton_run_args`), the Doris sentinels and the fix checks, with four exceptions found by an AST scan of every `docker run -d` and `run -i` argv in `evals/`: the Doris cluster (`doris_cluster_run_args` l.99), the MySQL engine and the moto stub (`mysql_backend.backend_container_run_args` l.137), the Neo4j database (`neo4j_backend.database_run_args` l.95) and the neo4j fix check's own database (`cve_2026_35402_neo4j_cypher.neo4j_container_args` l.94). The network a container gets is chosen apart from its confinement: in the planting layer by `cve_planting._network_args` (l.247, `PlantedArgs.network`, which the target, its probes and every launch built on `args.run_args()` or `args.network` take: the server launches of `cve_environments` other than `doris_db_env`, the kit launches, the mcpvault, vibe-trading, scrapling and contextforge fix checks), by `_holder_args` (l.204) and by `_sentinel_args` (l.235, for a bridge-alias sentinel; a bound sentinel, a stand-in and an address setup always join the holder); by `cve_planting_base.no_network_args()` (l.197), which `_network_args` and `nuisance_confinement.single_container_run_args` take; and by a literal `--network` in each backend module (the servers, the persistent containers, the Doris sentinels), in `doris_db_env` and in eleven fix checks (a bridge in atlassian, apify, jenkins, facebook-ads, gitlab, googleapis, figma and neo4j, `none` in python-notebook's server and in the flyto and n8n holders).
5. **A persistent backend is recreated only for a missing memory bound.** `ensure_doris` (l.87), `mysql_backend._ensure_container` (l.130), `neo4j_backend._ensure_database` (l.88) and `Responder.ensure` (l.68) keep a running container when `nuisance_confinement.running_with_bound` (l.37) finds it running with `HostConfig.Memory` at the bound. A container started with another hostname, alias or resolver option would be kept silently. `run_nuisance vet` and `run` remove the built backend containers (the responders, the apify stand-in, Neo4j) before their rebuild (`evals/nuisance_run_containers.py`), the pulled ones (the Doris cluster, the MySQL engine and moto) are persistent by design. On this host the Doris cluster, the MySQL engine and moto are running now.
6. **The stand-in.** `evals/docker/Dockerfile.stand-in` (l.14) inlines a replay server in its `ENTRYPOINT` (no `COPY`: the fingerprint hashes Dockerfile instructions only, and `test_no_dockerfile_copies_from_the_build_context` forbids it): a request matching a captured `(scheme, method, target)` gets its status, body and only its `Content-Type` and `Location` headers; any other request gets `404` with an empty body and a `miss <scheme> <method> <target>` line on stderr, which `DockerPlanting.remove_stand_in` (l.99) logs as `stand-in for <host> had no capture for: ...` (l.103). A `HEAD` to a target captured only for `GET` misses too. Both rules require that a stand-in answer any other request "with the error the real software gives" (holdout rule, What a fixture seeds and serves; nuisance rule v3, Stand-ins, "for an input it does not recognize"), and that it quote the request "only where its source quotes it". `evals/public_stand_ins.py` validates a capture (`StandInCapture` l.40: host, global unicast address, date, command, request headers, routes) and `evals/capture_stand_in.py` writes one (`capture_record` l.51, `main` l.90). The three committed captures, `evals/stand_ins/example.com.json` (2026-11-02, 7 routes), `demo.ckan.org.json` (2026-11-02, 1 route) and `api.apify.com.json` (2026-11-02, 2 routes, `Authorization: Bearer calib-token`), carry no answer for an unknown path. Probed from this host on 2026-11-03 at a random path: `example.com` answers `404` with its 576-byte page on both schemes (and `405` to a `POST`); `http://demo.ckan.org` and `http://api.apify.com` answer `301` with `Location` quoting the request path on `https` (`https://api.apify.com:443/<path>` for apify); `https://api.apify.com` answers `404` with a 153-byte JSON body; `https://demo.ckan.org` did not answer within 30 s. No body quotes the path in these answers. At the first recapture of Step 5 (2026-11-03), `https://demo.ckan.org` answered `404` with its HTML page of about 11 KB, which quotes the probed path 57 times, in its language selector (`<option value="/fr/<path>">` and its siblings), and `example.com` answered `404` with a 577-byte `text/html; charset=utf-8` page and no `Location` on both schemes. The stand-in serves both ports for every host (`_SERVED_PORTS = (80, 443)`), the apify API stand-in being a persistent singleton (`apify_backend._API_STAND_IN`) that mounts the committed capture.
7. **Fingerprints and baselines.** `cve_baseline.ENVIRONMENT_PATHS` holds `cve_environments`, `cve_layout`, `cve_planting_base`, `cve_planting_docker`, `public_stand_ins` among others, so every acceptance and holdout fixture fingerprint moves with this plan; a stand-in target adds its capture and the stand-in Dockerfile; CVE-2025-66335 hashes `evals/doris_backend.py` through `backend_sources`. `nuisance_fingerprint.nuisance_fixture_fingerprint` (parts l.51) hashes the patched Dockerfile's instructions, the launch, the host, the AST of `nuisance_confinement.py` (`CONFINEMENT_SOURCE`, l.55), the backend record and what it serves (each backend module, `closed_network.py`, `responder_backend.py`, the built Dockerfiles, the apify capture and leaf) and the benign calls. It does not cover `cve_planting_base.confinement_args`, which `nuisance_confinement_args()` calls, nor `cve_planting_base.no_network_args`, which `single_container_run_args` calls: a change to either moves no nuisance fingerprint. `evals/baselines/` holds `honeypot_e2e.json` and `judge_isolation.json` only, no `cve/` and no `nuisance/`, and no holdout run, nuisance run or gate run has taken place (both logs, 2026-11-03).

## Decisions

Taken by the maintainer before this plan:

1. **The layout root becomes traversable**: `root.chmod(0o755)` at the top of `build_layout` and `build_empty_layout`, in the module the repository and the kit share, so both arms of the layout check, the leak guard and every calibration path see one root. The fixture workarounds (CVE-2026-3680, CVE-2026-5603 and CVE-2026-5323 moved their working directory, CVE-2026-4270, CVE-2025-11489 and CVE-2025-66335 run as the host user) are not reverted here: repairing a fixture is calibration.
2. **The values that reach a server stop naming the audit**: the backend hostnames become `doris`, `mysql`, `moto` and `neo4j`, served by Docker network aliases on the backend bridges (and `--hostname doris` on the cluster). The container, image, network, holder and sentinel names and the labels stay. A Docker check proves what a target container sees (hostname, `/etc/hosts`, environment).
3. **No host search domain**: no container the three suites start for a fixture reads the host's search domain. `--dns-search .` goes on every container that has its own network stack, through a shared helper, and a container that joins a holder reads the holder's file.
4. **The stand-in answers what the real host answers for a path it does not have**: the capture records the real host's answer to a path that does not exist, one per scheme served, and the stand-in replays it for every request its routes lack. The format and the loader validate it, and the maintainer recaptures `example.com`, `demo.ckan.org` and `api.apify.com` with their leaves unchanged.

Taken in this plan, on the code, the rules and the measurements:

5. **The resolver option goes where a container gets its own network stack, never in `confinement_args()` (maintainer decision).** `cve_planting_base` gains `resolver_args()` (`["--dns-search", "."]`, Docker's documented spelling for no search domain, measured to remove the line) and `own_network_args(network)` (`["--network", network, *resolver_args()]`), and `no_network_args()` becomes `own_network_args("none")`. Every container with its own network stack takes the option where its network is chosen (Context 4): the holder (`_holder_args`); every container launched without a holder, on `--network none`, on the closed network or on a backend bridge (the target and its probes through `_network_args`, the nuisance single-container launch through `no_network_args()`, `doris_db_env`, each backend module's server launch); the backends and their singletons (the Doris cluster and its sentinels, the MySQL engine and moto, the Neo4j database, the ten responders and the apify stand-in); a sentinel or a stand-in only when it joins no holder (the bridge-alias sentinel, the fix checks' responders and the neo4j fix check's sentinel); and the fix checks' own-network launches. A container that joins a holder (the target and its probes behind a holder, the stand-ins, the bound sentinels, the address setups, the n8n stub, the flyto and n8n fix checks' joiners) never takes it: it reads the holder's `resolv.conf`. `confinement_args()` does not change, since every container takes it, joiners included. Rejected: the option in `confinement_args()`, one edit for every launch, which would put on every joiner an option Docker's documentation lists as not supported in `container:` mode and Docker 29.9 accepts and ignores (while refusing `--dns`), an argv that states a resolver setting the container does not get. The four argv that carry no confinement (the Doris cluster, the MySQL pair, the Neo4j database, the neo4j fix check's database) take `own_network_args()` like the others: dropping capabilities on a database engine is not this plan's change.
6. **The rest of `resolv.conf` stays as Docker writes it, and is recorded.** `--dns-search .` leaves the host's copied `options edns0 trust-ad`, Docker's comment lines naming the host's resolver file and its upstream (`ExtServers: [host(127.0.0.53)]`), and, under `--network none`, the LAN's resolver address. No `docker run` option removes the comment lines, which name a host path, so only a fixture-owned file mounted at `/etc/resolv.conf` would remove them all, and such a mount collides with a file place the planting supports at that path (`test_a_file_place_over_resolv_conf_beside_a_bridge_alias_fails_the_probe`). Setting the options or the nameserver alone would leave the comments naming the host, so this plan does neither, and the holdout and nuisance log entries quote the file a target reads after the change.
7. **The reverse lookup is recorded, not changed.** The names the maintainer kept (decision 2) reach a server that reverse-resolves an address through Docker's embedded DNS (Context 3). The Docker check of decision 2 records that answer beside the hostname, `/etc/hosts` and environment, and the log entries state it. Renaming the per-launch holders and networks would leave the persistent backend containers and the admission's recorded `backend.network` names, so it is a change of its own.
8. **A persistent backend container is recreated when its launch changes, not only its memory bound.** `nuisance_confinement.running_with_bound` and `carries_memory_bound` give way to a launch label: each persistent container (the Doris cluster, the MySQL engine and moto, Neo4j, the ten responders, the apify stand-in) is started with `--label mcp-auditor-cve-launch=<digest of its run argv>`, and `ensure` keeps a container only when it runs with the digest of the argv it would start now. Without it the running Doris cluster and MySQL pair would keep their old hostname, aliases and resolver file silently (Context 5), and the same trap would come back with the next launch change, as it came with the memory bound. The digest covers the memory bound, so the bound's recreation is kept. A label does not reach the server. `MEMORY_BOUND_BYTES` and the two functions go, with their tests.
9. **The new names.** `DORIS_HOST = "doris"`, `MYSQL_HOST = "mysql"`, `MOTO_HOST = "moto"`, `NEO4J_HOST = "neo4j"`, each in its backend module, each the alias of its container on its bridge (`--network-alias`), the Doris cluster also `--hostname DORIS_HOST`, `MOTO_ENDPOINT = f"http://{MOTO_HOST}:5000"`, and `NEO4J_URI = f"bolt://{NEO4J_HOST}:7687"` as a new constant the Dockerfile parity test reads. Each name is the software's own name, which carries no word of the audit, and each is unique on its closed bridge. The host-side tools (`_doris_sql`, the `docker exec` provisioning) keep addressing the containers by container name.
10. **The holdout side of the Doris value is a harness change, the card is calibration.** The `--db-host` value lives in `cve_environments.doris_db_env` and `doris_backend`, harness modules the nuisance doris server and the kit's doris builder share, so it changes here as an instrument change, logged. The rule makes a fixture repair calibration: CVE-2025-66335 goes back to calibration for the items the card check reported (gap 2, the hostname, and gap 3, `launch_options` declaring `mcpaudit-doris`), and its calibration agent confirms the fixture on the new value and rewrites the card. The same holds for decision 1: the harness change opens no version (the rule's text, the list of places and the layout's nodes, contents, ownership and mount modes are unchanged, and the root's permission bits are how the harness honours "with the layout mounted and the checkout as its working directory" for a server under the unprivileged account), but it touches every layout place's reach, so the route check runs again on every layout place and the layout check on every target, which `run_holdout calibrate` does (`confirm_admission`), and each target whose fixture took a workaround goes back to calibration for it.
11. **The nuisance side is the maintainer's repair window.** The doris `launch` (`--db-host`), the mysql benign call's `db_endpoint` and the `ENV` of `Dockerfile.mysql` and `Dockerfile.neo4j` are "the launch", "the arguments of a benign call" and "the address of a backend" (nuisance rule v3, The benign call), repaired by the maintainer before any audit and logged as such. `Dockerfile.neo4j-vuln`, a fix-check image whose `ENV` its fix check overrides, changes too, so no committed image names the audit.
12. **The nuisance fingerprint covers the confinement's and the resolver's options.** `parts` gains the values of `nuisance_confinement_args()` and of `resolver_args()`, beside the AST of `nuisance_confinement.py`. The rule's fingerprint covers "the host, the launch", and both option sets are part of the launch; today a change to `confinement_args()` (a later process bound) moves no nuisance fingerprint (Context 7), and neither would a change to `resolver_args()`, which the nuisance launches take from `cve_planting_base` through `no_network_args()` and `own_network_args()`. Every nuisance fingerprint moves once, before any nuisance run or gate run, and none is stored.
13. **The layout tree's modes stop following the host's umask.** `_git` runs with `umask=0o022` (and creates the empty layout's checkout directory), and the workspace dotenv is written at 0644, so the tree is readable by the unprivileged account on a host whose umask is stricter than this one's. It is the same defect as the root's (Context 1) on another machine, and the inner nodes move from 0775 and 0664 to 0755 and 0644, the same for every target.
14. **The default answer (amended by the maintainer on 2026-11-04, after Step 5 stopped on CKAN's page).** The capture command records, for every capture, the host's answer to one generated path that does not exist (`/` and 16 hex digits, recorded as `probed_target`, the plain probe) with `GET`, on `http` and on `https`, the two schemes the stand-in image serves for every host, with the same request headers as the routes. The stand-in chooses, for a request: the exact route; for a `HEAD`, the `GET` route of the same target without its body (RFC 9110 §9.3.2 defines `HEAD` as `GET` without content, and the `example.com` capture shows the same status for both); otherwise the default of the request's scheme, without its body for a `HEAD`. Both rules ask for "the error the real software gives" and let the stand-in quote the request "only where its source quotes it, in the source's wording", so a default may quote the probed target wherever the real answer quotes it, in its `Location` (the `301` of `http://demo.ckan.org` and `http://api.apify.com`) or in its body (the 57 quotes of `https://demo.ckan.org`'s 404 page, Context 6), and at replay the stand-in puts the request's target in each place the probed one sits. The first wording refused a body that quotes the probed target, which stopped Step 5 on CKAN's real page. Five rules keep the substitution measured rather than guessed:
    1. **Where.** `Location` receives the request target as sent on the wire (`self.path`, the target `http.server` holds). The body receives it only when its media type (the first `Content-Type` value, before any `;`, stripped and lowercased, so `text/html; charset=utf-8` is `text/html`) is `text/html` or `application/json`. A default whose body quotes the probed target under any other media type, or with no `Content-Type`, and a default whose header other than `Location` quotes it, are refused by the capture command and by the loader: a refused capture beats a guessed substitution.
    2. **Escaping.** In a `text/html` body the inserted value is escaped with markupsafe's table, the one CKAN's Jinja uses: `&` to `&amp;` (first), `<` to `&lt;`, `>` to `&gt;`, `"` to `&#34;`, `'` to `&#39;`. Python's `html.escape` writes `&quot;` and `&#x27;` instead, so neither it nor a markupsafe dependency is used: the replay server and `public_stand_ins.body_quoting` write the table out. In an `application/json` body the value is inserted as the content of a JSON string, `json.dumps(value)[1:-1]`.
    3. **Decoded or raw.** Whether a host inserts the URL-decoded path or the raw percent-encoded one is a fact to measure. Besides the plain probe, the capture sends on each scheme a second read-only `GET`, the form probe, whose path is the probed target followed by `FORM_SUFFIX = "%3Cx%3E%22%27"`, and compares its answer with the plain one. When the plain body quotes the probed target `n` times, the form probe must answer with the same status and media type and quote its own target `n` times in one form only: raw (`<probed_target>%3Cx%3E%22%27`, which either escaping leaves as is) or decoded (`<probed_target><x>"'` passed through `body_quoting` for the media type: `&lt;x&gt;&#34;&#39;` in HTML, `<x>\"'` in JSON), the 16 hex digits appearing nowhere else in its body. That form is the default's `path_form`, `"raw"` or `"decoded"`, and `null` when the plain body quotes nothing (the form probe's body then holding the 16 hex digits nowhere). Anything else (another status or media type, a quote in another escaping such as `&#x27;` or `<`, a mix of the two forms, another count) raises before the file is written. So the form probe also checks that the host escapes with the table of rule 2. Only `path_form` is recorded from the form probe: its suffix is a constant of the capture module, so the measurement is reproducible from `probed_target`. At replay, for `"decoded"` the body receives `urllib.parse.unquote(target)`, for `"raw"` the target as sent, then `body_quoting` for the media type in both cases (a no-op on a fully percent-encoded target, which guards a client that sends a quote unencoded).
    4. **Ambiguity guard.** The loader refuses a default in which the probed target's 16 hex digits appear anywhere but inside an occurrence of the probed target (their count in the body and in each header equals the probed target's), so a substitution never rewrites an unrelated value. `path_form` is a required field: `"decoded"` or `"raw"` when the body quotes the probed target, `null` otherwise, any other value or a missing key refused. Substitution applies to the defaults only: a captured route is replayed verbatim, whatever its body holds.
    5. **No flaw rides on it.** No target that declares a stand-in reaches it through its flaw (every kept place is a sentinel or a layout node), so a quoted target never carries what reaches the stand-in through a flaw.

    A method other than `GET` and `HEAD` gets the `GET` default (`example.com` answers `405` to a `POST`), and its `miss` line still names it. One default per scheme keeps the format at the maintainer's decision, and no target that declares a stand-in sends another method.
15. **The other words found stay with their campaigns.** The fixture words of Context 2 (`calib-token`, `# cve-rebind`, `benign`, `stub`, `seed`, `calib`) break the rules' limit on words chosen by the author. They are fixture content: the re-admission campaign (nuisance rule v3) and the holdout recalibration repair them, and a later token change recaptures `api.apify.com`. The layout's neutral token and git identity are the layout, which the holdout rule exempts and ADR 031 freezes, and the nonces and the nonce account are exempt by name. The `<segment>` placeholder reaches no server today. The holdout log entry lists them.

### `evals/docker/Dockerfile.stand-in`

The inlined replay server, read as plain Python:

```python
capture = json.load(open('/stand-in/capture.json'))
routes = {(r['scheme'], r['method'], r['target']): r for r in capture['routes']}
defaults = {d['scheme']: d for d in capture['defaults']}
HTML_TABLE = (('&', '&amp;'), ('<', '&lt;'), ('>', '&gt;'), ('"', '&#34;'), ("'", '&#39;'))  # markupsafe's, & first

def answer(scheme, method, target):  # -> (status, headers, body)
    route = routes.get((scheme, method, target))
    if route is None and method == 'HEAD':
        route = routes.get((scheme, 'GET', target))
    if route is not None:
        return route['status'], route['headers'], route['body']  # verbatim, never substituted
    sys.stderr.write('miss %s %s %s\n' % (scheme, method, target))
    default = defaults[scheme]
    probed = default['probed_target']
    headers = [(name, value.replace(probed, target) if name.lower() == 'location' else value) for name, value in default['headers']]
    body = default['body']
    if default['path_form'] is not None:
        body = body.replace(probed, quoted(target, default))
    return default['status'], headers, body

def quoted(target, default):
    value = urllib.parse.unquote(target) if default['path_form'] == 'decoded' else target
    media = media_type(default['headers'])  # first Content-Type before ';', stripped, lowercased
    if media == 'text/html':
        for raw, escaped in HTML_TABLE:
            value = value.replace(raw, escaped)
        return value
    return json.dumps(value)[1:-1]  # application/json, the only other media type the loader lets quote
```

`replay` sends the status, the `Content-Type` and `Location` headers of the answer, `Content-Length` of its (substituted) body encoded in UTF-8, and writes the body unless the method is `HEAD`. The header comment: a request matching a route gets it verbatim, a `HEAD` the `GET` route of its target without the body, any other request the capture's default for its scheme (the real host's answer to a path it does not have), with the request's target wherever the captured answer quoted the probed one: in `Location` as sent, in an HTML or JSON body in the form the capture measured (`path_form`), escaped with markupsafe's table for HTML and as a JSON string's content for JSON; and a `miss` line on stderr. The table is written out because the image carries no markupsafe, and `html.escape` writes `&quot;` and `&#x27;`, which CKAN does not.

## Edge cases

- A server that now reads the layout at start under the unprivileged account: the leak guard or the layout check may report a nonce in the ordinary surface or a break that the 0700 root hid. `run_holdout calibrate` names it, the holdout log records it, and the target goes back to calibration. On the acceptance targets (`run_cve_benchmark --calibrate`), a failure stops the implementation and is reported to the maintainer.
- The git target (CVE-2025-68143) mounts `/srv` read-write as the host user: the 0755 root keeps its owner's write bit, so `git_init` still writes `.git`.
- A host whose umask is stricter than 0022: the tree is still 0755 and 0644 (decision 13). A `.git` object git writes read-only (0444) stays readable.
- A container joining a holder carries no resolver option and reads the holder's file, which the holder's option sets: the target and its probes behind a holder, the stand-ins, the bound sentinels, the address setups, the n8n stub, the flyto and n8n fix checks' joiners. A file place planted at `/etc/resolv.conf` mounts over the generated file as before.
- A launch that sits on two networks (googleapis's responder and server) carries the resolver option once, with its first `--network`: the option is per container, not per network. The Doris cluster joins `_DORIS_LLNET` later through `docker network connect`, and its resolver settings are the container's, set at its start: the Verification's `docker exec` reads the cluster's `resolv.conf` after the connect, and a `search` line there stops the implementation.
- `no_network_args()` now carries the resolver option, so a test that pins `PlantedArgs.network` to `("--network", "none")` or `("--network", <network>)` (`tests/unit/test_cve_planting.py`, `test_cve_planting_stand_ins.py`, `test_cve_planting_endpoints.py`) takes `no_network_args()` or `own_network_args(network)` as its expected value; a pin of the joiner's `("--network", f"container:{holder}")` stays as it is. `_joins_holder` in `cve_environments` reads the first two items, which do not change.
- A persistent container started before this change (the running Doris cluster, MySQL engine and moto): its label is absent, so the first `ensure` removes and starts it once, Doris re-provisioning its schema as every `ensure_doris` does. A responder, Neo4j or the apify stand-in is also removed by `vet` and `run` before their rebuild. A launch argv holding a host path (the apify stand-in's mounts) changes its digest when the checkout moves, which recreates it once.
- The Doris front-end under its new hostname: the cluster is recreated fresh with no volume, so no metadata carries the old one. If it fails to become healthy, the implementation stops and reports.
- The apify stand-in after the recapture: it loads its capture at start, so a singleton started before keeps the old one until `vet` or `run` replaces it, or its launch label changes. The Verification runs `vet` after the recapture.
- A committed capture without defaults, or whose defaults lack `path_form` (the working tree's `example.com` recapture of 2026-11-03), no longer loads: the code lands with the three recaptures, before the closing check.
- `https://demo.ckan.org` did not answer the Context probe on 2026-11-03 and answered Step 5's first recapture the same day: a recapture that fails on it stops the maintainer (Files, `evals/stand_ins/*.json`).
- CKAN's form probe answered otherwise than its plain probe (another status, such as a `400` for the encoded characters, or another media type), or quoting in an escaping other than markupsafe's (`&#x27;`, `&quot;`), or partly decoded and partly raw: the capture raises before writing and Step 5 stops on its stop rule, a refused capture beating a guessed substitution.
- A body that quotes the probed target inside a longer path (`/fr/<probed_target>` in CKAN's selector): the substring is the probed target, so the request's target replaces it and the prefix stays (`/fr/<request target>`), as the host would write it.
- A request target with a query string: `self.path` holds it, so `Location` and the body receive the whole target, query included; the probes carry no query, so this form is not measured, and no target that declares a stand-in is known to send one to an uncaptured path.
- A `"decoded"` default and a request whose percent-encoding is not UTF-8: `urllib.parse.unquote` replaces the bytes with U+FFFD, a guess for an input no declared target sends.
- A `"raw"` default and a client that sends `"` or `<` unencoded: the target is escaped per the media type all the same, so the page stays well-formed.
- A `HEAD` that falls to a default: the substituted body is not sent, and `Content-Length` is that of the substituted body.
- A captured route whose body contains a string equal to a default's probed target: replayed verbatim, substitution applying to the defaults only.
- A recapture that resolves `example.com` or `demo.ckan.org` to another address: the stand-in is pinned to the new one (it is a global unicast address, which the loader checks), and the leaf, issued for the name, is unchanged.
- A request whose method is neither `GET` nor `HEAD` on an uncaptured target: the `GET` default, and its `miss` line names the method (decision 14).
- A `Location` in the default that does not quote the probed target: replayed verbatim.
- A default whose body quotes the probed target under a media type other than `text/html` and `application/json` (with or without parameters such as `; charset=utf-8`), or with no `Content-Type`, or whose other header quotes it, or whose 16 hex digits appear outside the probed target: the capture command raises before writing, the loader refuses a hand-edited one (decision 14 rules 1 and 4).
- The four holdout targets that declare a stand-in: their cards cite the capture date, which the recapture moves, and their calibration agents update the card in the recalibration.
