# Audit resilience to model and transport failures

## Context

Exploratory runs on 2026-10-16 and 2026-10-17, with large open-weight models through OpenRouter and with Anthropic models, lost whole eval passes to failures of a single model call or of the transport, not to anything the server under audit did. Four defects, all in the system under test; this plan fixes the first three:

1. **An unreadable answer crashes the audit.** `LLM.generate_structured` raises `UnparseableOutput` after its parse attempts, and nothing in the graph catches it: `call_model` (`graph/refusals.py`) only turns a `ProviderRefusal` into a reported step. The whole audit stops, everything already tested is lost, and the usage of every call made so far is lost with it. Seen on Haiku 5.5 (`judge_response`), GLM 5.3 and Opus 4.8 (`observe_step`, and once `judge_response`): 9 e2e passes lost out of 22 in two days.
2. **A payload with a lone UTF-16 surrogate crashes the transport.** The generator wrote an argument holding `\ud800`. The MCP SDK's `stdin_writer` (`mcp/client/stdio`, `model_dump_json`) raises `PydanticSerializationError: ... surrogates not allowed`, the writer task dies, the MCP session falls and the audit with it. Nothing reached the server.
3. **An effort the model does not support is accepted silently.** The `openrouter` provider accepts every effort from `none` to `max`, but each model supports a subset that OpenRouter publishes (`reasoning.supported_efforts` in `/api/v1/models`): GLM 5.3 `low`, `high`, `max`. A run sent `medium` to GLM 5.3 and measured a setting it was not given (OpenRouter documents that it maps an unsupported effort to the nearest supported level for some models, so the setting was remapped or unknown).
4. **Anthropic with thinking cannot force the schema tool.** The `anthropic` provider binds the output schema as a tool (`adapters/llm_tool_binding.py`), and the API drops a forced `tool_choice` when thinking is on (`UserWarning: tool_choice is forced but thinking is enabled ... Tool calls are not guaranteed`). The model sometimes answers without the tool, every attempt parses to nothing, and defect 1 follows. `langchain-anthropic` 1.7.5 (installed) supports Anthropic's native structured output, `with_structured_output(method="json_schema")`, which needs no tool, but Anthropic's structured output requires `additionalProperties: false` on every object, and the installed `anthropic` 1.11.0 `transform_schema` rewrites the open `AuditPayload.arguments: dict[str, Any]` to an object that can only be empty: every generated payload would come back with `arguments: {}`. Fixing this needs a schema change (for instance the arguments carried as a JSON string on that path), so **defect 4 is out of this plan** and tracked separately. With change 1, its failures stop losing audits and become visible missed steps.

The project already treats a provider refusal as a visible coverage hole rather than an error to absorb or a crash: the step is reported with the provider's message, the case stays unjudged, the audit carries on, and `--ci` exits 3 on an incomplete audit. Defect 1 is the same situation with another cause, so it takes the same treatment, and the decision is to generalize the refused step into a **missed step** that carries its cause. Defect 2 takes the treatment the destructive-payload guard already gives a payload that must not be sent: the case is blocked with its reason (ADR 013's `BlockedPayload`). The justification of each change holds without any eval measurement: an auditor must not throw away a whole audit for one unreadable answer or one unencodable string, and must not run a setting it was not given.

## Approach

Three changes to the system under test, one commit each, in this order, each under the paired gate like any change to the system under test:

1. **Missed steps** (domain, graph, report, CLI, evals that read refused steps). `RefusedStep` becomes `MissedStep` with a `cause`; `call_model` catches `UnparseableOutput` as well as `ProviderRefusal`; every reader of refused steps reads missed steps. The usage of an unreadable answer reaches `provider_usage` (and `judge_usage` for a judge step), which also closes the long-standing "usage lost on a total parse failure" defect for in-graph calls.
2. **Unencodable payloads blocked** in `AuditedServer`, before `call_tool`.
3. **OpenRouter effort checked against the model's published efforts** when the model is built.

The two eval policies that read refused steps keep their meaning for a refusal and decide the new cause explicitly: the CVE acceptance layer replays an attempt with a missed step and no detection whatever the cause (it already does so for a refusal: the run says nothing of detection); the holdout counts an attempt with a missed step and no detection as a non-detection with no replay, whatever the cause: the rule refuses to replay a refused audit because replaying until no step is missed would keep the best of several attempts, and that argument holds for an unreadable answer, which is the model's behaviour, not the infrastructure's. Before this change the holdout retried an unreadable answer as an infrastructure error (the crash became a `LaunchError`), so this is a change in how the rule is read, logged in `docs/holdout-log.md`. The acceptance layer's broader replay is a change to the CVE gate's instrument, logged in `docs/labeling-log.md`.

### Change 2: unencodable payloads blocked

`src/mcp_auditor/domain/payload_safety.py` (or a new `domain/payload_encoding.py` if `payload_safety.py` would pass 300 lines): add `unsendable_reason(arguments: dict[str, Any]) -> str | None`, walking the arguments (dict keys, strings, lists, nested dicts) and returning `"argument {path} holds a character that cannot be encoded as UTF-8"` for the first string that raises `UnicodeEncodeError` on `.encode("utf-8")`, else `None`.

The blocked case keeps its payload, surrogate included, in the state and the report. That is safe on every output path checked: `render_json` uses `json.dumps` (ASCII escapes), the Markdown report prints the arguments through `repr`, the dry-run table and the prompts use `json.dumps`, and the prompts skip blocked cases; a checkpoint write replaces the surrogate by `?` (lossy, no crash). Test scenario 8 pins `render_json` and `render_markdown` on such a report.

`src/mcp_auditor/domain/audited_server.py`: `attempt` checks `destructive_reason` then `unsendable_reason`, and returns `BlockedPayload(reason=...)` for either before reaching the client. Chains go through the same `attempt`, so a chain step is covered too.

### Change 3: OpenRouter effort checked against the model

`src/mcp_auditor/adapters/chat_model_factory.py` (or a new `adapters/openrouter_models.py` holding the lookup): before building the `openrouter` model, fetch `https://openrouter.ai/api/v1/models` with `httpx` (a 10 s timeout, short because it is metadata and a hanging network must not hold an audit for minutes), find the entry whose `id` is the model, and read `reasoning.supported_efforts`. When the resolved reasoning is `None` (no reasoning sent, e.g. a model override), no fetch and no check. When the list is present and the resolved reasoning is not in it, raise `ValueError(f"Model {model!r} on OpenRouter supports reasoning efforts {', '.join(efforts)}, got {reasoning!r}.")`. When `supported_efforts` is `null` (OpenRouter's "no allowlist"), build without a warning. When the model is absent from the listing, its `reasoning` object is omitted (OpenRouter's "no effort selection" while the project still sends one), or the request fails or times out, log one warning and build the model unchecked: the check must not make an audit depend on a metadata endpoint being up. The fetch happens once per model built (the generator and the judge are built separately; cache per process by model id). The lookup is injectable (a fetch function or an `httpx` transport passed down from `make_chat_model`'s callers, defaulting to the real endpoint), and the cache is owned by that injected object rather than a module global, so tests neither hit the network nor leak cache state between tests. The existing `tests/unit/test_chat_model_factory.py` cases that build an `openrouter` model with a reasoning (`test_openrouter_builds_glm_at_low_reasoning_on_open_routing`, `test_openrouter_pins_the_listed_hosts_without_fallback`) would otherwise call `openrouter.ai` from the unit suite, or wait on the timeout in a sandbox without network: they get a fake listing.

## Edge cases

- **A missed judgment** leaves the case unjudged: the honeypot gate already reads such a cell as `uncovered` for the run, and the flip cause `UNCOVERED` already exists.
- **A missed generation** leaves the tool with no cases: coverage gap and missed step both reported, as with a refusal.
- **A missed chain observation** ends the chain at the step it reached and judges what it has, as with a refusal.
- **Both causes in one audit**: reported separately; the holdout counts the run as incomplete (not detected), the acceptance replays it.
- **Resuming a checkpoint written before this change** holds `RefusedStep` objects and `refused_steps`/`chain_step_refused` channels. It is not resumable after the upgrade, and the failure would be silent, not a traceback: LangGraph's msgpack hook revives a Pydantic class it cannot import as its plain field dict (with a deprecation warning, not an error), and `aget_state` reads only the channels the current graph declares, so the old refused steps would vanish from the resumed report (an incomplete audit could read complete) and a chain resumed mid-way would hit a `KeyError` on `chain_step_missed`. `resume_or_reset` therefore detects the old channels explicitly: when resuming is requested, it scans the thread's stored checkpoints through `graph.checkpointer.alist({"configurable": {"thread_id": thread_id}})` (every namespace, subgraphs included) for a `refused_steps` or `chain_step_refused` key in `checkpoint["channel_values"]`, and fails with a clear message ("checkpoint written by an earlier version, run without --resume"). A pre-change checkpoint that holds neither key (no refusal, no chain started) resumes normally. No migration shim (the checkpoint is local and the audit can be rerun).
- **A surrogate inside a dict key or a nested list** is found by the walk; a valid astral character (a correctly paired surrogate, emoji) encodes and is not blocked.
- **OpenRouter metadata says `mandatory: true` and the setting is `none`**: `none` is not in `supported_efforts` for such a model, so the check rejects it with the same message.
- **OpenRouter `supported_efforts: null`**: no allowlist, built without a warning.
