# Standards pass on the shared test support

## Context

The shared test support was reviewed against the coding, testing and architecture standards of `CLAUDE.md`: the builders of `tests/unit/support/` that several areas import, the fakes of `tests/fakes/`, the support servers, shims, Docker prerequisites and the given/then of the integration tests in `tests/integration/support/`, the project guards of `tests/unit/project/` and `tests/integration/committed/project/` (the code standards scan and its debt list, the glossary checks, the retired-word guard and its exemptions, the README and PyPI README policies, the workflow path filters), and the conftests. That is 100 files. Seven modules of `tests/unit/support/` (`backend_launch_specs.py`, `doris_launch.py`, `fake_ckan.py`, `fake_control_planes.py`, `fake_searxng.py`, `registered_responders.py`, `fake_sshd.py`) were reviewed with the backend fixtures and are outside the pass. The three honeypot servers are outside it too. No production module changes: `src/` and `evals/` are only read.

A mechanical inventory listed the functions over 20 body lines, over 3 arguments and the files over 300 lines (38 items, 3 files over 300 lines), and the public names no other file names. Fifteen reviewers then read the code, eleven file by file and four across the whole support (architecture and placement, duplication and missing concepts, ubiquitous language, what the fakes and builders let the tests catch), and reported 86 findings. Twelve more verified each finding against the code, rejected those that did not hold or traded one standard for another, merged the duplicates, and designed the fix of the rest. Five decision points then went to two independent reviewers and to a third that challenged the recommendations (Decisions). This plan carries the 52 fixes that survived (11 of medium value and 41 of low value, 49 small and 3 medium in effort). Of the other findings, 28 are merged into a fix, 4 are rejected and 2 are left outside the standards passes (Decisions).

The fixes fall into a few families:

- the follow-ups the earlier passes left to this one: the shared holdout-run support that imports one area's `layouts` module, the two copies of the NVD flaw builder, the call-index container sweep fake, the two scripted attempt helpers, the misnamed replay read server and the nuisance builders. The follow-up on `report_builders.py` is closed with no move: the eval export test would reuse little of it, and `grammar_inputs.py` is already the shared report builder. The one on `image_prerequisites` is already paid: each integration test's prerequisite fixture names its own services;
- shared support that depends on one area's support (`detection_holdout_runs.py` on `tests/unit/detection/support/layouts.py`, `censuses.py` on `tests/unit/census/support/advisory_sources.py`), and support used by one area only that sits in the shared directory (the retired-word scan, fifteen admission mutators, three committed-admission lookups);
- the same knowledge written twice: the holdout run conditions of the two holdout-run supports, the fictional stand-in capture of the unit and integration supports, the paths of the support servers, the empty planting spec, the fault-injection budget, the registered backend fixture, the lost-connection response;
- fakes that do not behave like the component they stand for: a scripted graph that makes the client relaunch and reports no relaunch, a container sweep that answers by call index in the one command that lists two tag sets;
- two loopholes of the project guards: the code standards scan owns a given by file stem only, so a committed test imports its unit namesake's given, and the retired-word scan skips three files that no longer need it;
- names in a moved sense (place ids called flaw ids, a census flaw called a CVE, "counted" for a launch counter, "holdout copy", an unqualified walk, "refused" for a predicate), builder parameters never passed, and public names used only in their module.

## Approach

Each fix below is small and stands on its own, except where the order notes of its section say otherwise. They are grouped in twelve sections, in the order they are implemented:

1. the vocabulary guards: the retired-word scan moves to the project area's support and loses its dead machinery;
2. the shared fakes (`launch_audit_fakes.py`, `tests/fakes/mcp_client.py`, `chat_model.py`, `provider_errors.py`);
3. the container sweep fake and the scripted attempts;
4. the holdout-run supports, which section 3 leaves untouched;
5. the census builders, before section 6, since the nuisance walk builder reads the draw envelope section 5 adds;
6. the nuisance builders;
7. the planting, launch and fix-check fixture builders;
8. the stand-in capture builders;
9. the integration support servers and their paths;
10. the integration detection givens, after section 9, which renames the read servers they launch;
11. the integration auditor and network givens;
12. the code standards scan, last: its tightened given/then ownership refuses a given borrowed across directories, so every move of a given or a committed test comes before it.

Within a section, the fixes are listed in the order the section's note gives. A reference such as "fix 5.2" names a fix of this plan, and "section 4" a section of it. The reasons, changes, tests and risks of a fix were written by its verifier before the sections were ordered and before the five decisions below: where one of them weighs the order against another section, the section notes and the order above win, and where it conflicts with a decision, the decision wins. A rejected finding is never implemented, even when a fix's text discusses how it would interact.

## Decisions

- **The container sweep fake is narrowed, not rewritten** (fix 3.1). `FakeContainerSweep` answers each listing by call index, whatever the tags it is asked about. That is exact for every command that lists one tag set, whose tags the `listed_tags` asserts already pin, and wrong for the nuisance gate on a server with a built backend, which lists the backend tags at its start and both sets at its end: a start removal that lists the server tags, or an end sweep that drops the backend tags, turns no gate test red today. Only the three gate tests on `on_the_ckan_backend` move to the tag-keyed `DockerHost`, with its rebuild and its benign call composed into the gate harness (without the benign call, a sweep that drops the backend tags stays green, since nothing starts a backend container after the start removal). `FakeContainerSweep.running` raises on a second tag set, so its precondition is enforced, and its false docstring is corrected. The full rewrite into one tag-keyed fake (about fifteen files) is rejected: it buys no catch beyond those three tests. `test_nuisance_vet.py:95-98` and the gate test with no backend stay on the index fake, since each lists one tag set.
- **The code standards scan owns a given by directory** (fix 12.3). CLAUDE.md places a test's given and then "in that directory's support/", so the owner of `<dir>/support/test_x_given` is `<dir>/test_x.py`, not every file named `test_x.py`. 22 test stems exist both in `tests/unit` and in `tests/integration`, and two committed tests borrow their unit namesake's given today. The two borrowings are paid first (the PyPI README rendering helpers move to a plain project support module, `the_copy_resolution` to `tests/unit/support/committed_nuisance_admission.py`), then the scan is tightened in its own `test(project)` commit, red first, with the `CONTRIBUTING.md` sentence. The scan is a project test, not an instrument in the glossary's sense, so the change has no labeling-log entry. A given or then beside its test, the form the CLAUDE.md example shows, is owned too; no file of the tree uses it. `Violation.symbol` keeps the last component, so the scan tests and the debt keys do not move.
- **The three dead entries of the retired-word scan's `_SKIPPED` go, in their own `test` commit** (fix 1.5). They date from the time the glossary test's given held the patterns themselves. The glossary tests now use the fictional word `oldterm`, and the scan without those entries finds 0 violations and 0 stale entries. The result is the same on today's tree, but the scan reads three more files, so it is stricter, and the commit says so. The two modules that hold the patterns and the exemptions stay skipped.
- **The two integration read servers are renamed, not merged** (fix 9.1). They share a `PATH=NONCE` parser and a two-line tool body, about six lines, while their nine flags serve two families of tests. `detection_replay_read_server.py` becomes `read_server.py`, the server `a_read_server` and `READ_SERVER_PATH` already name, which the client transport, cancellation, failure, resume and kit client tests use as much as the detection replay. `detection_read_server.py` becomes `calibration_read_server.py`, the server of the calibration check and the survey, and its path constant `CALIBRATION_READ_SERVER_PATH` joins the other support server paths in `support_servers.py`, which ends the homonym `READ_SERVER_PATH`.
- **The two scripted graphs of `launch_audit_fakes.py` fold into one** (fix 2.1), named `graph_calling(calls)` with the body of `graph_reporting_its_relaunches`. With the noisy client, `graph_calling` made the client relaunch and returned a report with no relaunch, a state the real graph cannot produce (`AuditedServer` relaunches on a lost connection and the graph records it). The fold is a fake fixed, declared in its commit message: three asserts (`tests/unit/cve/test_cve_launch_audit.py`, `tests/unit/detection/test_detection_audit.py`, `tests/unit/nuisance/test_nuisance_audit_once.py`) go from `ServerHealth(2, 1)` to `ServerHealth(2, 1, relaunches=1)`. Fixes 2.1 and 3.1 are the two fixes that change what tests check, and fixes 1.5 and 12.3 the two that make a scan stricter; every other fix is a refactoring of the tests, a dead name removed, or a false docstring or test name corrected.
- **Left outside the standards passes**, listed so they are not lost: the given `a_confined_context` of `tests/integration/support/test_confined_launch_given.py` copies the composition root's private `_launch_context` (`src/mcp_auditor/cli.py`), which only a public launch-context builder in `src/` would remove; the retired-word guard retires whole families of identifiers (`FIX_CHECK_TARGETS`, `ConclusionVerdict`, `print_verdict`, `PhaseUsage`, `calibrate_all`, `DrawWalkStep`, `primary_controls` among them) that `docs/glossary-log.md` does not list, a docs change to the vocabulary map; the production message "the census has no draw walk to follow" of `evals/cve/nuisance/admission/walk_record.py` and its `match=` in `tests/unit/nuisance/admission/test_nuisance_walk.py`; and a retired-word pattern for "holdout copy", a vocabulary-rule decision (fix 6.8 renames the last identifier carrying it).
- **Identifiers that plans cite and whose name a fix changes or removes, and modules that plans cite and that a fix moves or renames, get a line in `docs/glossary-log.md`**, in the commit that changes them. A function or constant that moves to another module under the same name gets no line, since a search finds it (`the_copy_resolution` of fix 12.3, the three committed-server lookups of fix 6.7, the detection `ScriptedAttempts` of fix 3.2), and neither does `stand_in_capture.STAND_IN_HOST`, whose readers keep the name as an alias of `fictional_stand_ins.HOST` (fix 8.1). - A move leaves no module behind that re-exports the moved name: a name moved out of a module that keeps importing it passes `pyrefly` as an implicit re-export, so each move is checked by the AST scan of Verification.
