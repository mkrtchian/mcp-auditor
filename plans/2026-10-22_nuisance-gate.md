# Nuisance suite: the gate on the acceptance servers

## Context

The nuisance suite's input side (`plans/2026-10-22_nuisance-admission.md`) and its measurement side (`plans/2026-10-22_nuisance-measurement.md`) are built: the walk, the admission schema, the fix-check driver, the counter, the run orchestrator, the server-unit statistic and the report. The measurement plan left out the gate the rule defines for the acceptance servers, as a later plan decided by the maintainer on 2026-10-22: the figure is what the first nuisance run needs, the gate is what a change of the auditor needs once the detection features arrive.

`docs/nuisance-rule.md` (version 1), section Run conditions and statistic, last paragraph, prescribes it: "Only the acceptance servers with a current target are gated. The gate audits them in a run of its own, under the run conditions its baseline records, as the CVE acceptance gate does (ADR 024). A nuisance run does not audit them, and a gate run audits no other server. The baseline is recorded under `evals/baselines/`. It is recorded from a green gate and never under a red one (ADR 016). An acceptance server not flagged in any run of the baseline is gated. When a candidate raises an alarm on it, the alarm is re-tested under the replay rule of ADR 016, with the numbers the baseline file records. The gate fires when the alarm reproduces. A server with an alarm in some runs of the baseline is unstable, and a new alarm on it is reported as inconclusive. The other rules of ADR 024 apply, with the server in place of the target and an alarm in place of a miss." Its Reading section adds that "the traces of the acceptance servers may be opened and their alarms analyzed, and a gate run writes their per-case report as a graded CVE run writes it". Its Versioning section says a change to the counter or to the grammar resets the gate's baseline.

This plan builds that gate. It admits no server, records no baseline and runs no real audit: no acceptance server is admitted until the maintainer's deferred admission session, so `python -m evals.run_nuisance gate` prints that no acceptance server is admitted and exits 0, as `run` does with no admitted server. Every module is testable with fakes and crafted admitted servers. It edits no rule and no ADR, moves no grammar fingerprint, no counter fingerprint, no acceptance fixture fingerprint and no baseline. Each committed step gets a dated `docs/nuisance-log.md` line naming its commit and stating that no acceptance server is admitted, so no gate runs, on the model of the measurement entries.

## Approach

The gate is a sibling of the CVE acceptance gate, not a generalization of it. Decision recorded (CLAUDE.md spirit, settled here): the CVE gate's modules (`cve_gate`, `cve_recording`, `cve_session`, `cve_session_recording`) carry three things the nuisance gate has none of, the detection ladder with its move-between-rungs reporting, the unchecked-credit outcome of ADR 030 and the planting layer, and they gate in the opposite direction (a miss there, an alarm here). A shared generic gate would take a flag or a strategy for each of these. The nuisance gate reuses the primitives that are already generic, `gate.ReplayRule`, `baseline.BaselineStatus`, `baseline.RecordingRef`, `recording.RecordingRefused`, `gate_verdict.GateVerdict`, `eval_session.Refused`/`TreeState`/`tree_drift`/`read_tree`, and the nuisance modules (`nuisance_audit`, `nuisance_counter`, `nuisance_counting`, `nuisance_images`, `nuisance_run.default_deps`'s pieces), and mirrors the CVE gate's logic in its own small modules. Each mirrored function names its CVE counterpart in the plan so a reviewer can diff them.

Eight parts, each standing alone, written test-first (its tests from Test scenarios run red before its code), and keeping `pytest`, `ruff` and `pyright` green:

1. **The gate population and the run's acceptance exit** (`nuisance_walk.py`, `nuisance_run.py`, new `nuisance_population.py`, `run_nuisance.py`): which admitted servers the gate audits, and the fix that keeps a nuisance run from auditing an acceptance server admitted outside the walk.
2. **The gate's conditions** (`holdout_conditions.py`, new `nuisance_gate_baseline.py`): the run conditions a gate baseline records, and the narrower readiness check the gate needs.
3. **The baseline model and its files** (`nuisance_gate_baseline.py`): one file per server under `evals/baselines/nuisance/`, load, write and integrity.
4. **The pure gate** (new `nuisance_gate.py`): compare a candidate server to its baseline, settle a pending alarm by replays, judge the run.
5. **The recording decision** (new `nuisance_gate_recording.py`): first recording, confirmation, replacement, all or none.
6. **The gate audit** (`nuisance_audit.py`): one run of one server with the incomplete-attempt retry the acceptance gate uses.
7. **The gate session** (new `nuisance_gate_session_model.py`, `nuisance_gate_session.py`, `nuisance_gate_session_recording.py`): the orchestrator, with git, Docker, the clock, the audit and the baseline directory injected.
8. **The report, the export, the `gate` subcommand, the living docs and the log** (new `nuisance_gate_report.py`, `export.py`, `run_nuisance.py`, docs).

Parts 1 to 5 are pure. Part 6 wraps the existing nuisance audit. Part 7 is unit-tested with a faked harness, as `test_cve_session.py` and `test_nuisance_run.py` do.

## Part 1: the gate population and the run's acceptance exit

`evals/nuisance_walk.py`: `_acceptance_servers(census)` becomes public as `acceptance_servers(census) -> set[str]` (rename, behavior unchanged: the normalized packages of every `BENCHMARK_FLAWS` flaw the census classifies, current and dropped targets alike). A new pure `current_acceptance_servers(census) -> set[str]` returns the packages of the current targets only, `server_of(target.cve_id, census)` for each `CVE_TARGETS` target whose id the census classifies (today `npm:@modelcontextprotocol/server-filesystem`, `PyPI:mcp-server-git`, `npm:mcp-server-kubernetes`, `npm:mcp-fetch-server`, checked against the committed census while writing this plan). It imports `CVE_TARGETS` from `evals.cve_targets`, which `nuisance_walk` does not import yet: check that this adds no import cycle (`cve_targets` imports nothing from the nuisance modules).

`evals/nuisance_run.py`: `run_population(walked, admission)` gains a third parameter, `acceptance: set[str]`, the set `acceptance_servers` returns. Today an admitted server leaves the audited set only through a walk mark, and the walk marks no acceptance server (none of the 86 reached flaws is an acceptance server's, `BENCHMARK_FLAWS` being outside the draw order, `census_grouping.in_draw_order`). The rule admits the acceptance servers with a current target "outside the walk", so once admitted they would be audited by the nuisance run, which the rule forbids ("A nuisance run does not audit them"). With the parameter, an admitted server whose package is in `acceptance` gets the `FigureExit(package, "an acceptance server")` row, once, whether or not the walk marked it, and is never audited. `run_nuisance._run` passes `acceptance_servers(census)`, and the three existing `run_population(walked, admitted)` calls in `tests/unit/test_nuisance_run.py` pass `set()`. `nuisance_run.py` is at 293 lines, and this parameter with Part 7's module-level `benign_call` takes it past 300, so `RunPopulation`, `run_population`, `_MARK_REASONS` and `_standing_exit` move into a new `evals/nuisance_population.py`, `_standing_exit` made public as `standing_exit(server) -> str | None` since the gate reads it too (the imports of `nuisance_run`, `run_nuisance`, `tests/unit/support/test_nuisance_run_given.py` and `tests/unit/test_nuisance_run.py` follow, and the population tests move to a new `tests/unit/test_nuisance_population.py`).

`evals/nuisance_gate_session.py` (Part 7) holds `gate_servers(admission, current) -> list[AdmittedServer]`: the admitted servers whose package is in `current` and for which `standing_exit` gives `None`, in admission order. An admitted current acceptance server that does not run over stdio or in a container would fail its launch at every gate run and keep the gate not comparable for a standing reason, so it stays out of the gate set, and `outside_gate(admission, current) -> list[FigureExit]` lists it with its reason for the report. It also reports the current acceptance packages no admitted server carries, `sorted(current - admitted packages)`, as "not admitted" in the report: informational, never a reason for not comparable, since an acceptance server can legitimately stay out of the admission (a server with no counted tool fails `load_admission`'s `_counted_tool_problems` and never enters the file, the log carrying its exit).

## Part 2: the gate's conditions

The gate runs under the nuisance run's conditions, which are the holdout's apart from the number of runs (ADR 033): the holdout budget `holdout_run.HOLDOUT_BUDGET`, no tools filter, the chain settings and the tool call timeout of `evals/holdout_conditions.json`, and its own number of runs. Decision recorded (the rule's "under the run conditions its baseline records, as the CVE acceptance gate does", read here): the gate gates what the figure measures, so its conditions are the figure's. Its default number of runs is `NUISANCE_GATE_RUNS = 3` (in `nuisance_gate_baseline.py`), the CVE gate's `CVE_RUNS`, lowerable with `--runs` like the nuisance run, and recorded in the baseline, so a change of it is a whole reset taken only from a green gate (ADR 020, under ADR 024).

`evals/holdout_conditions.py`: extract from `HoldoutConditions.require_ready` a method `require_chain_settings(self) -> None` that raises `Refused("holdout run conditions not ready", [_CHAIN_NOT_SET])` when any of `chain_budget`, `max_chain_steps`, `tool_call_timeout` is `None`. `require_ready` keeps its behavior (it still reports the chain reason beside the cutoff and price reasons, in one `Refused`: it calls a private `_chain_reasons()` shared with the new method, so its single refusal is unchanged). The gate calls `require_chain_settings` and not `require_ready`: a gate needs no cutoff (it computes no split) and no price (it reports no cost), so a gate under a model with no logged cutoff is not refused for a holdout fact.

`evals/nuisance_gate_baseline.py`: `class NuisanceGateConditions(BaseModel)` with `runs: int`, `budget: int`, `tools_filtered: bool`, `provider: str`, `model: str`, `judge_model: str`, `reasoning: str | None`, `judge_reasoning: str | None`, `chain_budget: int`, `max_chain_steps: int`, `tool_call_timeout: int`, `grammar_fingerprint: str`, `counter_fingerprint: str`. `tools_filtered` is always `False`, since the rule fixes "no tools filter" for every nuisance audit, and recorded anyway because ADR 024 lists the tools filter among the conditions a baseline records. A builder `gate_conditions(settings: Settings, conditions: HoldoutConditions, runs: int) -> NuisanceGateConditions` (calls `require_chain_settings` first, then reads `settings.resolve_*` as `run_cve_benchmark._run_conditions` does, `HOLDOUT_BUDGET`, `tools_filtered=False`, `cve_baseline.grammar_fingerprint()` and `nuisance_counter.counter_fingerprint()`). The counter fingerprint is a condition, so a change to `nuisance_counter.py` or `nuisance_counting.py` is a whole reset, as the rule's Versioning section requires, and so is a change to the grammar.

## Part 3: the baseline model and its files

`evals/nuisance_gate_baseline.py`, the sibling of `cve_baseline`'s baseline half:

- `NUISANCE_GATE_BASELINE_DIRECTORY = Path(__file__).parent / "baselines" / "nuisance"`.
- `class NuisanceServerBaseline(BaseModel)`: `server_package: str`, `status: BaselineStatus`, `conditions: NuisanceGateConditions`, `fixture_fingerprint: str`, `replay_rule: ReplayRule`, `commit: str`, `recorded_at: str`, `runs: list[bool]` (flagged per run, True for an alarm), `confirms: RecordingRef | None = None`, `replaces: RecordingRef | None = None`, `image_ids: dict[str, str]` (provenance, not a condition, ADR 024). Methods: `alarmed(self) -> bool` (any run flagged) and `gated(self) -> bool` (`status == CONFIRMED and not any(self.runs)`).
- `baseline_file_name(server_package: str) -> str`: the package with every character outside `[A-Za-z0-9._-]` replaced by `_`, plus `.json` (`npm:@modelcontextprotocol/server-filesystem` gives `npm__modelcontextprotocol_server-filesystem.json`). A package carries `:` and `/`, which a file name cannot hold portably. Decision recorded: one file per server, as ADR 024 has one per target, so a fixture change resets one server by deleting one file.
- `load_baselines(directory) -> dict[str, NuisanceServerBaseline]` keyed by `server_package`, raising `ValueError` when a file's name is not `baseline_file_name` of the package it holds (the mirror of `cve_baseline.load_baselines`'s stem check). An absent directory loads as empty, as `Path.glob` on a missing directory already yields nothing.
- `write_baseline(directory, baseline)`: atomic, through a `.json.tmp` and `os.replace`, as `cve_baseline.write_baseline`.
- `baseline_integrity(baseline) -> list[str]`: the held runs against the runs the conditions claim, doubled for a confirmation (ADR 023), the mirror of `cve_baseline.baseline_integrity`.
- `server_reset(server_package) -> str` and `WHOLE_RESET: str`, the reset instructions the gate and the recording print, mirrors of `cve_gate.target_reset` and `cve_gate.WHOLE_RESET`: delete `evals/baselines/nuisance/<file>` in the commit that changes the server's fixture and record it twice at one commit with `--server <package>`, or delete `evals/baselines/nuisance/` in a commit of its own and record twice.
- `condition_mismatches(baselines, candidate: NuisanceGateConditions) -> list[str]`, the mirror of `cve_gate.condition_mismatches`, one line per baseline file and differing field.

The fixture fingerprint of a server is `nuisance_images.nuisance_fixture_fingerprint(server)`, unchanged: the rule's fixture fingerprint, which covers the patched Dockerfile, the launch, the host, the counted tools with their classes' categories and the benign calls.

## Part 4: the pure gate

New `evals/nuisance_gate.py`, the mirror of `cve_gate.py` with the server in place of the target and an alarm in place of a miss.

- `class ServerOutcome(StrEnum)`: `HELD` (gated, no alarm in any candidate run), `REGRESSION` (gated, the alarm reproduced), `ALARM_NOT_REPRODUCED`, `PENDING_REPLAY`, `NOT_GATED`, `INCONCLUSIVE` (an alarm on a server with an alarm in the baseline), `FIXTURE_CHANGED`, `NO_BASELINE`, `INCOMPLETE`, `NOT_RUN`.
- `class ServerCandidate(BaseModel)`: `server_package: str`, `fixture_fingerprint: str`, `runs: list[bool]` (flagged per completed run), `completed: bool` (False when a run did not complete).
- `class ServerComparison(BaseModel)`: `server_package`, `outcome`, `candidate_runs: list[bool]`, `replays: list[bool] = []` (True: the alarm reproduced), `detail: str | None = None`.
- `class NuisanceGateResult(BaseModel)`: `verdict: GateVerdict`, `reasons: list[str]`, `servers: list[ServerComparison]`.
- `compare_server(baseline: NuisanceServerBaseline | None, candidate: ServerCandidate) -> ServerComparison`, in this order: no baseline gives `NO_BASELINE`. A fixture fingerprint that differs gives `FIXTURE_CHANGED` with `server_reset`. An exploratory baseline gives `NOT_GATED` (confirm it at its commit, or delete it). A confirmed baseline with an alarm gives `INCONCLUSIVE` when a candidate run is flagged, `NOT_GATED` otherwise, the detail naming the baseline's flagged runs (`flagged in k of n baseline runs`). Then a candidate that did not complete gives `INCOMPLETE`. A candidate with no flagged run gives `HELD`, else `PENDING_REPLAY`. Decision recorded: the rule calls a server "unstable" when "an alarm in some runs" of the baseline, and a server flagged in every baseline run is read the same way, since no new alarm can show on it either.
- `settle(comparison, replays: list[bool | None], rule: ReplayRule) -> ServerComparison`: a replay that did not complete gives `INCOMPLETE`, else `rule.decide_replays`, `REGRESSION` on True and `ALARM_NOT_REPRODUCED` on False, unchanged while undecided. The mirror of `cve_gate.settle`.
- `judge(comparisons, mismatches) -> NuisanceGateResult`: `NOT_COMPARABLE` on any condition mismatch (with `WHOLE_RESET`) or any `NOT_RUN`, `INCOMPLETE` or `PENDING_REPLAY` server. Else `RED` on any `REGRESSION`. Else `GREEN`, its reasons naming the `ALARM_NOT_REPRODUCED`, `FIXTURE_CHANGED` and `INCONCLUSIVE` servers, plus "no server is gated" when no comparison is `HELD` or `ALARM_NOT_REPRODUCED`. An `INCONCLUSIVE` server does not block green: it is reported, as the honeypot gate's `CellOutcome.INCONCLUSIVE` is.
- `exit_code(verdict) -> int`: 0 green, 1 red, 3 not comparable.

## Part 5: the recording decision

New `evals/nuisance_gate_recording.py`, the mirror of `cve_recording.py`:

- `class ServerRecording(BaseModel)`: `server_package`, `conditions: NuisanceGateConditions`, `fixture_fingerprint`, `commit`, `recorded_at`, `runs: list[bool]`, `completed: bool`, `image_ids`.
- `decide_recording(existing, recording, comparison) -> NuisanceServerBaseline | RecordingRefused`: a recording with a run that did not complete is refused. With no file, it is exploratory with the default `ReplayRule()`. Over an exploratory file, it confirms by adding its runs after the first's (ADR 023), refused when the conditions, the fixture fingerprint or the commit differ. Over a confirmed file, it replaces it only when neither the fixture nor the conditions changed (a reset starts from a deleted file) and the comparison is `HELD`, `NOT_GATED`, `INCONCLUSIVE` or `ALARM_NOT_REPRODUCED`, refused on `REGRESSION` (never under a red gate, ADR 016) and on any other outcome. `INCONCLUSIVE` is in the green set here, where `cve_recording._GREEN` has no counterpart: a server already unstable stays recordable over.
- `leaves_gated_set(existing, written) -> bool` and `decide_recordings(decisions)` (all or none), mirrors of `cve_recording`'s.

## Part 6: the gate audit

`evals/nuisance_audit.py` gains the gate's run of one server. The audit that produces a report is the existing `nuisance_audit(server, attempt)` (launch failure and throttling retried, `NUISANCE_INFRA_ATTEMPTS`). On top of it:

- `@dataclass(frozen=True) class GateRun`: `flagged: bool`, `report: AuditReport`.
- `async def gate_run(server: AdmittedServer, audit: Callable[[], Awaitable[AuditReport | DroppedRun]]) -> GateRun | None`: at most `cve_audit.INCOMPLETE_ATTEMPTS` (3) calls of `audit`. A `DroppedRun` returns `None` at once (the run did not complete, as `graded_despite_missed_steps` returns `None` on a throttled or skipped attempt). A report with a counted alarm (`flagged_tools(report, counted_tools(server))` non-empty) stands whatever step was refused. A report with no counted alarm that `is_incomplete` (a step refused by the provider or unreadable) is attempted again, with a console line naming the attempt and the cause. A complete report stands. When every attempt is incomplete without an alarm, it returns `None`.

Decision by the maintainer (2026-10-22): an audit of the gate with no counted alarm in which a step was refused or came back unreadable is attempted again, up to three attempts, and the run does not complete when every attempt stays incomplete, so on a gated server the gate is not comparable, and a recording of the server is refused whatever its baseline. On a server that is not gated (no baseline, exploratory, or with an alarm in its baseline) the comparison reads as before, as ADR 024 makes only a gated target's incomplete run not comparable, and `compare_server` checks completion after those branches. A green gate then never rests on a missed step that could hide an alarm. This is the policy the acceptance gate applies to an incomplete attempt (`cve_audit.graded_despite_missed_steps`, its labeling log entry), with an alarm standing in place of a detection. It is not the nuisance run's policy, under which such an audit counts as not flagged without a retry, because the figure describes what a user sees and the gate decides changes. The gate's log entry records it, no rule version opens: the rule leaves the gate to "the other rules of ADR 024", which say nothing of an incomplete attempt.

## Part 7: the gate session

Three new modules from the start, split as the CVE gate splits its session across `cve_session_model`, `cve_session` and `cve_session_recording` (436 lines together): `evals/nuisance_gate_session_model.py` holds the value objects below (harness, options, written baseline, audit, session result), `evals/nuisance_gate_session.py` the population reads, `default_harness` and `run_gate`, `evals/nuisance_gate_session_recording.py` the recording refusals and the write. The split also lets `export.py` import `GateAudit` from the model module without pulling in the I/O-heavy session.

- `@dataclass(frozen=True) class NuisanceGateHarness`: `audit: Callable[[AdmittedServer], Awaitable[GateRun | None]]`, `benign_call: Callable[[AdmittedServer], Awaitable[str | None]]`, `rebuild: Callable[[Sequence[str]], None]`, `image_ids: Callable[[Sequence[str]], dict[str, str]]`, `read_tree: Callable[[], TreeState]`, `clock: Callable[[], str]`, `baselines: Path`. Built by `default_harness(conditions, concurrency)`, which composes `nuisance_audit`, `audit_once`, `build_auditor(conditions.budget)` (the budget read once, from the conditions the baseline records), `RunOverrides` from the conditions and `gate_run`, and reuses the benign-call connection of `nuisance_run.default_deps` (extract that inner `benign_call` into a module-level `benign_call(server, timeout)` in `nuisance_run.py` so both use it, behavior unchanged).
- `@dataclass(frozen=True) class NuisanceGateOptions`: `servers: list[AdmittedServer]` (already filtered by `--server`), `gate_packages: frozenset[str]` (every package of `gate_servers`, before `--server`), `conditions: NuisanceGateConditions`, `record_baseline: bool`. The baselines the session compares and checks for condition mismatches are the files whose package is in `gate_packages`, the mirror of `cve_session_model.GatedSession.baselines()` over `_BENCHMARKED`: a `--server` run leaves the other gate servers' files out of the comparison, not out of the mismatch check, and never reports them as orphans.
- `@dataclass(frozen=True) class WrittenBaseline`: `server_package: str`, `status: BaselineStatus`, `leaves_gated_set: bool`, the mirror of `cve_session_recording.WrittenBaseline` (which carries a `cve_id`, so it is not reused).
- `@dataclass(frozen=True) class GateAudit`: `server_package: str`, `run_index: int`, `flagged: bool`, `report: AuditReport`, the completed main runs for the report and the export, never a replay. The session result keeps the reports here only, and the report and the export group them by package.
- `@dataclass(frozen=True) class NuisanceGateSession` (the result): `audits: list[GateAudit]`, `gate: NuisanceGateResult`, `not_run: dict[str, str]` (package to the benign call's failure), `orphans: list[str]` (baseline files of servers not in the gate set), `written: list[WrittenBaseline]`, `recording_refused: list[str]`, `exit_code: int`. The exit code is the verdict's, except that a non-empty `recording_refused` gives 3, as `run_cve_benchmark._run_graded` overrides a refused recording to 3, so a green gate whose recording was refused never exits 0.
- `async def run_gate(options, harness) -> NuisanceGateSession`, raising `Refused` before any audit: load the baselines (an invalid file or a failed integrity check refuses, `REFUSED_BEFORE_ANY_LLM_CALL`). Under `record_baseline`, refuse a dirty tree and any condition mismatch (with `WHOLE_RESET`), as `cve_session_recording.recording_tree`. Rebuild the images of the gate servers. Send the benign call to every server (gathered): a failing server reads `NOT_RUN` with its reason and leaves the gate not comparable, and under `record_baseline` refuses the recording before any audit (the mirror of `cve_session._checked`). Audit the surviving servers `conditions.runs` times each (gathered, order kept). Compare each server, then, when no condition mismatches, replay each `PENDING_REPLAY` server one audit at a time until its baseline's `ReplayRule` decides or a replay does not complete (`replays.append(None if run is None else run.flagged)`), the mirror of `cve_session._replayed`. Judge. Under `record_baseline`, refuse on tree or baseline-file drift during the runs (`tree_drift`, reload and compare), then decide every server's recording and write all or none. A baseline file whose package is not in `gate_packages` is an orphan (an acceptance server no longer current or no longer admitted), reported by its file name and not compared.
- `run_gate` reads as the sequence of these steps, each a private helper right below it (newspaper rule, functions of about 20 lines), as `cve_session.run_gated` delegates to `_checked`, `_run_targets`, `_gate` and `_replayed`.
- The dirty tree does not refuse a comparison, as the CVE gate: the report records `dirty`. Tracing is not refused: the acceptance servers' traces may be read (rule, Reading).

## Part 8: the report, the export, the subcommand, the docs and the log

New `evals/nuisance_gate_report.py`: `class NuisanceGateReport(BaseModel)` with `conditions`, `commit`, `dirty`, `concurrency`, `servers: list[GateServerLine]` (`server_package`, `flagged_per_run: list[bool]`, `flagged_tools_per_run: list[list[str]]`, `raw_fail_per_run: list[int]`), `not_run`, `not_admitted: list[str]`, `outside_gate: list[FigureExit]`, `orphans`, `gate: NuisanceGateResult`, `written: list[str]`, `recording_refused: list[str]`, and a pure `server_lines(session: NuisanceGateSession, servers: Sequence[AdmittedServer]) -> list[GateServerLine]` that groups `session.audits` by package and reads each report through `flagged_tools(report, counted_tools(server))` and `raw_fail_count(report)` (the composition root assembles the report around it, commit and dirty from its own `read_tree()`, as `run_cve_benchmark._run_graded` does), and `render_markdown(report) -> str`: the verdict and its reasons, one row per server with its outcome, its runs as letters (`A` alarm, `.` none), its replays and its flagged tools, the not-run, not-admitted and outside-the-gate servers, the orphans and the recording lines. If the module passes 300 lines, `render_markdown` moves to a `nuisance_gate_markdown.py`, as the figure's `nuisance_report.py` and `nuisance_markdown.py` are split. The flagged tool names and the raw count are written here because a gate run, unlike a nuisance run, may be read (rule, Reading: "a gate run writes their per-case report as a graded CVE run writes it").

`evals/export.py`: `export_nuisance_gate_judged_cases(audits: list[GateAudit], report_path: Path)` writes `nuisance_gate_judged_cases.jsonl` beside the report, one line per judged single-step case (`_judge_input(case, tool_description)`) and per judged chain, each with `server_package` and `run_index`. Unlike `export_cve_judged_cases`, it carries the chains: a chain counts as an alarm (`nuisance_counter.tool_verdicts`), and the rule lets the acceptance servers' alarms be analyzed, so a chain alarm with no line would leave nothing to read. The chain line comes from a `_chain_judge_input(chain, tool_description) -> dict[str, Any] | None` extracted from `_chain_line` (the part with no ground truth: type, tool, description, category, goal, steps, verdict, justification), which `_chain_line` then extends with its expected verdict, its output unchanged. `GateAudit` is imported from `nuisance_gate_session_model`.

`evals/run_nuisance.py`: a `gate` subcommand with `--record-baseline`, `--runs` (default `NUISANCE_GATE_RUNS`), `--concurrency` (default `NUISANCE_CONCURRENCY`), `--server PKG` (repeatable, restricts the gate set, for a one-server reset, a package outside the gate set exits 2, checked after the "no acceptance server is admitted" exit), `--report` (default `output/nuisance_gate_report.json`), `--census`, `--admission`. It loads the census and the admission (absent file reads as empty), computes the gate set, and with no admitted acceptance server prints "no acceptance server is admitted" and exits 0 before any settings, Docker or LLM. Else it builds the conditions, runs the session, writes the report JSON, markdown and export, prints the markdown and the baseline lines (recorded with its status and next step, leaving the gated set, orphans), and exits with the session's code: 0 green, 1 red, 3 not comparable or refused (a refused recording included), 4 on a crash with its traceback (the `gate` handler catches any other exception itself, so `main`'s `ValueError` handling stays the census/admission refusal). The module docstring names the subcommand.

## Edge cases

- No admission file, or an admission with no current acceptance server: `gate` prints that no acceptance server is admitted, exits 0, reads no settings.
- A current acceptance server not admitted: listed as not admitted, the gate compares the others.
- An admitted acceptance server of a dropped target (`gemini-mcp-tool`, CVE-2026-0755): outside the figure as an acceptance server, outside the gate set (not current).
- A server's benign call fails: `NOT_RUN`, gate not comparable, a recording refused before any audit.
- A run drops after the infra retries, or stays incomplete over three attempts without an alarm: the candidate does not complete. On a gated server it reads `INCOMPLETE` and the gate is not comparable. On a server that is not gated it reads `NO_BASELINE` or `NOT_GATED` as before. A recording of that server is refused either way.
- An admitted current acceptance server that does not run over stdio or in a container: outside the gate set, listed with its reason, never audited.
- An alarm in an audit where a step was refused: the run stands as flagged.
- A replay that does not complete: `INCOMPLETE`.
- A recording refused once the runs are done (drift, an incomplete run): the report is written and ends with the reasons, exit 3 whatever the verdict.
- The counter changes: every baseline's conditions mismatch, not comparable with the whole reset printed.
- The grammar changes: `load_admission` refuses the admission first (its grammar fingerprint is stale, `nuisance_admission._fingerprint_problems`), so `gate` exits 3 as a malformed admission, before any baseline is read. The admission is redone under the new grammar (the rule's Versioning section applies the eligibility again), then the baselines mismatch on `grammar_fingerprint` and the whole reset is printed.
- An admission change that moves a server's counted tools, benign calls, launch, host or patched Dockerfile: that server's fixture fingerprint moves, `FIXTURE_CHANGED` with its own reset, the gate stays comparable on the others.
- A baseline file with a name that does not match its package: refused before any LLM call.
- `--record-baseline` from a dirty tree, or with a condition mismatch: refused before any audit.
