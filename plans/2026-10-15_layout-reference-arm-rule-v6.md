# Layout break detector: a valid reference arm, both versions, and the git fallback scope

## Context

The deployment-layout break detector (ADR 031, `docs/holdout-rule.md`) runs a mechanical no-LLM check before the exploits: it launches the server once with a reference arm (the rule's "an empty directory at each path of the layout") and once with the full layout, and calls it a break when the launch or `tools/list` succeeds without the layout and fails with it, or when a call that returned no error without it returns one with it. The reference arm is the control: it is what "without the layout" means.

The rule defines that reference arm uniformly as an empty directory at each layout path. This control is degenerate for a server that requires its scope to be a valid repository. The git target (CVE-2025-68143) launches `mcp-server-git --repository /srv/app`; `mcp-server-git` validates at startup that `--repository` points to a valid git repository and exits otherwise (`/srv/app is not a valid Git repository`). An empty directory at `/srv/app` therefore kills the server before `tools/list`, so the reference arm never succeeds, `layout_breaks` can never satisfy its "succeeds without, fails with" criterion, and the break detector is structurally blind on the git target. The damage is nil on today's acceptance layer (git is graded under the NORMAL arm, which starts fine because the layout provides the repository it needs, and a manual smoke-check confirmed no server breaks), but the blind spot is real for the holdout: a scope-requiring server that the layout actually broke by an erroring call would never be reported.

Two related defects sit in the same code and the same target. First, `confirm_admission` runs the break check on the vulnerable version only, while the rule says the layout check "launches each version once" and "when the layout breaks either version, both versions run in the fallback": the patched version is never checked for a break. Second, the git target's fallback scope is registered as `FallbackScope(DOCUMENTED_DEFAULT, path=/srv/app)` (`evals/cve_targets.py:274`, `FALLBACK_SCOPE = _PROJECT`), but `mcp-server-git`'s `--repository` is optional (each tool takes a `repo_path` argument per call), so the rule's third fallback branch applies: a server whose scope is optional is launched without one. The registered fallback is wrong twice over: it uses `DOCUMENTED_DEFAULT` where the rule asks for `OPTIONAL`, and its path `/srv/app` is the checkout the fallback exists to stop scoping to. The field is a card entry, not a live launch setting: the break detector only reports and the maintainer sets `launch_mode` by hand, and no builder reads `fallback_scope` (`_materialise` applies the module constant `FALLBACK_SCOPE` under the FALLBACK shape and `_git_launch` always passes `--repository /srv/app`, see the comment above `FALLBACK_SCOPE` in `evals/cve_environments.py`). It is read by `fixture_fingerprint` under the fallback launch-mode and it is what the rule records on the card (holdout-rule.md:201, "the fallback scope, when the target runs in the fallback"). Fixing the reference arm is what first lets the git break detector report a break, so the card the maintainer would then act on has to be right. The three ship together.

## Approach

Amend the rule to version 6: the reference arm is a minimal valid empty node at each layout path, by the node's type, rather than a bare empty directory. An empty directory stays an empty directory; the checkout node becomes an empty initialised repository (`git init`); the bare node becomes an empty bare repository (`git init --bare`). This keeps the control uniform (defined by node type, the same for every target, no per-target tailoring) and lets every scope-requiring server start under the control. The change is justified on the design flaw (a control that cannot start a server that needs content to exist), not to make a target pass: git's graded detection runs under the NORMAL arm and is unchanged, and no holdout target is drawn, so this is a pre-draw rule refinement, not a change that reacts to a result.

Conform the harness to the amended rule and to the existing rule: build the valid-by-type reference arm, run the break check on both the vulnerable and the patched version (a break on either is a break), and set the git target's fallback to `OPTIONAL`. Keep the route check and the nonce-leak guard on the vulnerable version, as the rule prescribes.

Accept the baseline reset the change forces, option (a) of the reset discussion. `build_empty_layout` lives in `evals/cve_layout.py`, which is in the fixture fingerprint's module set (`_ENVIRONMENT_PATHS`), so editing it moves every target's fixture fingerprint and the just-recorded acceptance baseline no longer compares. The reset is the governed nominal path (ADR 024: a fixture change resets the baseline; ADR 020: a reset is deletion in its own commit then two recordings at one commit), its cost is nil in governance (no target is gated, so nothing can be lost) and modest in compute (24 audits), and the content is expected identical (the graded run is unaffected by the reference arm). Do not open a module outside the fingerprint to dodge it: the module granularity is deliberate, a rare false-positive reset is the price of an instrument with no silent hole, and a line in the `fixture_fingerprint` docstring records that the environment modules are hashed whole, admission arm included, by choice of granularity.

## Code details

`build_empty_layout(root)` keeps its signature and stays host-side, but builds by node type instead of a flat `mkdir`. For the workspace anchor, an empty directory (`mkdir`). For the checkout anchor (`/srv/app`), `git -c init.defaultBranch=main init --quiet` into an empty directory (the spelling `_build_bare_repository` uses), under the same `_GIT_IDENTITY` and host user `build_layout` uses, so a server that validates its repository starts (`mcp-server-git` 2025.7.1 and 2025.9.25 both call `git.Repo(repository)` in `serve()` and return on `InvalidGitRepositoryError`; an initialised repository with no commit passes it). For the bare anchor (`/srv/app.git`), `git init --bare --quiet`. No commits, no remote, no `.env`: the reference arm carries none of the layout's content, it only makes each node a valid empty instance of its type. Reuse the module's `_git` helper. The built tree need not be byte-reproducible: the fixture fingerprint hashes module source, not the built tree, and the break detector reads only whether the launch and the calls succeed, not response bodies.

`_observe` gains a `version: TargetVersion` keyword parameter (default `VULNERABLE`), threaded to `target.launched(records, shape=shape, version=version)` (`CVETarget.launched` already accepts `version`). A new helper does a version's two launches and returns a small frozen value object pairing them:

```python
@dataclass(frozen=True)
class VersionObservation:
    reference: RouteObservations
    planted: RouteObservations
    nonces: tuple[str, ...]  # the planted arm's nonces; the reference arm plants none

async def _observe_version(target, places, version) -> VersionObservation:
    reference, _ = await _observe(target, (), places, shape=LaunchShape.EMPTY_LAYOUT, version=version)
    planted, nonces = await _observe(target, target.kept_places, places, version=version)
    return VersionObservation(reference, planted, nonces)
```

`confirm_admission` then reads `vuln = await _observe_version(target, places, VULNERABLE)` and `patched = await _observe_version(target, places, PATCHED)`, which keeps its body within the newspaper rule. The two-version break is a pure function, `layout_breaks_any(pairs)` over a sequence of `(reference, planted)` surfaces (`any(layout_breaks(ref, planted) for ref, planted in pairs)`), so the decision is golden-master testable: `layout_breaks_any([(vuln.reference, vuln.planted), (patched.reference, patched.planted)])`. The route check and `nonce_in_surface` read `vuln.planted` and `vuln.nonces` only, unchanged. `admission_gave_up` keeps its current single-observation signature `(target, planted)` and is OR-combined at the call site, `admission_gave_up(target, vuln.planted) or admission_gave_up(target, patched.planted)`, so its three unit tests in `tests/unit/test_cve_layout_check.py` stand unchanged.

The CVE-2025-68143 target sets `fallback_scope=_NO_FALLBACK_SCOPE`. `FALLBACK_SCOPE` (`evals/cve_environments.py:114`) and the filesystem target's use of it are out of scope and unchanged; only the git target moves, because only its scope is optional.

## Edge cases

The patched git twin also requires a valid repository at its scope; `build_empty_layout` is version-agnostic, so the same valid reference arm serves both versions, and the two-version break check now exercises the patched git under the control too. A server scoped to a plain directory (filesystem, kubernetes, fetch) now sees a `.git` directory inside `/srv/app` and a bare repository at `/srv/app.git` under the control, where it saw two empty directories: that changes listing bodies, which the break criterion ignores, not the error state of a call, so its break verdict is unchanged. The reverse asymmetry is also harmless: an empty repository can make a history-reading call (`git_log`, `git_show`) error in the reference arm where the layout's commits make it succeed, and the criterion counts only a call that errors with the layout and not without, so this is not a break. The git target's filter (`git_init`, `git_add`, `git_diff_staged`) works on an empty repository anyway. The git break detector, now able to start its control, could for the first time report a break on git; on today's layout it should not (the NORMAL arm provides the repository and the smoke-check found no break), and a break here would be a true finding to act on, not a regression.

The `OPTIONAL` fallback scope is recorded on the card only: no builder honours a per-target `fallback_scope` yet (`_git_launch` passes `--repository /srv/app` under every shape, and wiring the three shapes into the launch is deferred, see `evals/cve_environments.py`), so setting it changes no launch today. When it is wired, the git_init traversal exploit still reaches its targets through each tool's `repo_path` argument, so a launch without `--repository` does not disarm it. One consequence to record, and it is the rule's own logic, not a defect: `workspace-dotenv`, the one place git keeps, is routed by the dotenv documented default taken relative to git's scope (the parent of `/srv/app`, so `/srv`). The `OPTIONAL` fallback launches git with no scope, so `_documented_default` (`evals/cve_route.py`) has no scope to take the parent of and finds no route. So if the layout ever breaks git and the maintainer sets the fallback, the route check flags `workspace-dotenv` as unrouted, the admission fails on it, and git keeps zero places and leaves the acceptance layer, as CVE-2025-68145 did. A scope-requiring server that the layout breaks and whose only place cannot be routed without the layout scope is not measurable, so dropping it is the honest outcome, and the rule forbids a fallback scope that names the layout. It is inert today (git does not break under the layout), and it is why the card has to be right before the detector can first report a break on git.

## Governance

Rule v6 is a procedural refinement of the break detector's control, not an addition or removal of a layout place, and it is made before the first holdout draw and not in reaction to any result, so it stays within ADR 031's freeze (which governs the places, ADR 031:80) and ADR 028's pre-registration (the rule is versioned and its commit logged; ADR 028 rejected pinning the rule by a file hash). It needs no new ADR: it refines the mechanism ADR 031 already decided. The admissibility was reviewed and ratified against the governing texts: ADR 031 does not define the reference arm (it says only "succeed without the layout and fail with it", ADR 031:78), "an empty directory at each path" is a rule specification (holdout-rule.md:159), the Versioning clause makes the version bump mandatory on any edit of the file regardless, the change can only make a target fail a break check and never pass (so it goes with the freeze's "never changed to make a target pass"), and the valid-by-type arm is by node type, not by server type (the thing ADR 031 rejected). The reset follows ADR 024 and ADR 020. The commit order is strict: all code, including the class and function docstrings in `_ENVIRONMENT_PATHS` modules, lands in the implementing commit, then the baseline deletion in its own commit, then the two recordings. The model for the implementation is Opus 4.8 or Fable, never 5.5, as for the rest of this work.
