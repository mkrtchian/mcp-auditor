# Standards pass on the backend fixtures

## Context

The backend fixtures of the CVE benchmark were reviewed against the coding, testing and architecture standards of `CLAUDE.md`: the modules of `evals/cve/backends/` that no eval fingerprint hashes (`__init__.py`, `apify.py`, `gitlab_responder.py`, `lifecycle.py` and `neo4j.py`), the 59 modules of `evals/cve/nuisance/fix_checks/` (the fix-check fixtures of the admitted nuisance servers and their shared sibling modules), their tests (`tests/unit/cve/backends`, `tests/unit/nuisance/fix_checks`, `tests/integration/committed/cve/backends`, `tests/integration/committed/nuisance/fix_checks`) and two support modules of `tests/unit/support/` that mostly serve them (`fake_sshd.py`, `registered_responders.py`). That is 139 files. The 22 other modules of `evals/cve/backends/` are outside the pass, since `nuisance_fixture_fingerprint` or a detection target's `backend_sources` hashes them. Their tests are in the pass, they are not.

A mechanical inventory listed the functions over 20 body lines, over 3 arguments and the files over 300 lines (20 items, 3 files over 300 lines). Sixteen reviewers then read the code, twelve file by file and four across the whole area (architecture and responsibilities, duplication and missing concepts, ubiquitous language, the test suite as a whole), and reported 78 findings. Ten more verified each finding against the code, rejected those that did not hold or traded one standard for another, merged the duplicates, and designed the fix of the rest. This plan carries 42 of the fixes that survived (1 of high value, 10 of medium value and 31 of low value, 40 small and 2 medium in effort) and 3 the consolidation added (fixes 7.6, 8.11 and 9.3). Of the other findings, 23 are merged into a fix, 9 are rejected (four at consolidation) and 4 are deferred to a change of their own (Decisions).

The fixes fall into a few families:

- the follow-up the pass on the CVE benchmark core left to this area: the two parity tests of the backend lifecycle, which check little more than the hand-off of their arguments since the nuisance provisioner delegates to the kit's `backend_launch`;
- tests in the wrong place: fix-check builders tested in the backend test files, backend support modules imported by a shared support module, a test file named after a builder it never touches;
- false docstrings and comments in the fix checks, read by admission agents as reference text: modules renamed since, mechanisms described wrongly (flyto, figma, googleapis, ckan, netlicensing), and the witness called a nonce in about 33 modules;
- knowledge written twice inside a fix check (gravitino's server launch, flyto's two builders, netlicensing's stand-in files, n8n's sentinel address) or in the tests (the import scan, the quiet backends, the planting specs), and givens and thens that abstract nothing.

## Approach

Each fix below is small and stands on its own, except where the order notes of its section say otherwise. They are grouped in nine sections, in the order they are implemented:

1. the backend test support, first, since the moved modules are imported by sections 2 and 3;
2. the backend lifecycle tests;
3. the scope and the thens of the backend tests;
4. the committed backend checks;
5. the apify and neo4j modules;
6. the fix-check command and registry tests;
7. the fix-check builders;
8. the false docstrings and comments of the fix checks, after section 7, whose code they describe;
9. the witness and the fixtures' names, since the sweep renames the parameters and words the earlier sections leave, and the entry of the nuisance suite log, last, which records the real fix check run on the finished plan.

Within a section, the fixes are listed in the order the section's note gives. A reference such as "fix 5.2" names a fix of this plan, and "section 4" a section of it. The reasons, changes, tests and risks of a fix were written by its verifier before the sections were ordered: where one of them weighs the order against another section, the section notes and the order above win. A rejected finding is never implemented, even when a fix's text discusses how it would interact.

## Decisions

- **Bringing every image a fix-check builder stands up to date is left to a change of its own, after this plan** (the deferred findings on `apify-responder`, `googleapis-witness-responder`, `facebook-ads-sentinel` and `neo4j-backend`).
```python
import ast, asyncio, hashlib, sys
from pathlib import Path
from evals.cve.nuisance.fixtures import FIX_CHECK_FIXTURES
from tests.unit.nuisance.fix_checks.support.test_fix_check_launches_given import HAND_BUILT_LAUNCHES
try:
    from tests.integration.committed.nuisance.fix_checks.support.recorded_exchanges import recorded
except ImportError:
    from tests.unit.nuisance.fix_checks.support.recorded_exchanges import recorded

def code_digest(path: Path) -> tuple[str, str]:
    tree = ast.parse(path.read_text())
    for node in ast.walk(tree):
        body = getattr(node, "body", None)
        if isinstance(body, list) and body and isinstance(body[0], ast.Expr) and isinstance(body[0].value, ast.Constant) and isinstance(body[0].value.value, str):
            node.body = body[1:] or [ast.Pass()]
    strings = [n.value for n in ast.walk(tree) if isinstance(n, ast.Constant) and isinstance(n.value, str)]
    return hashlib.sha256(ast.dump(tree).encode()).hexdigest()[:16], hashlib.sha256(repr(strings).encode()).hexdigest()[:16]

async def main() -> None:
    for f in FIX_CHECK_FIXTURES:
        fields = (f.flaw, f.effect_class, f.aim.pattern, f.aim.flags, repr(f.witness), repr(f.planting_host),
                  f.vulnerable_service, f.patched_service, f.server_patched_service, f.backend_services,
                  f.builder.__module__, f.builder.__qualname__)
        print("fixture", fields)
        print("  exploits", [await recorded(f, call) for call in f.exploits])
        print("  benign", [await recorded(f, call) for call in f.benign_calls])
    for key, launch in sorted(HAND_BUILT_LAUNCHES.items()):
        print("launch", key, launch())
    if "--code" in sys.argv:
        for path in sorted(Path("evals/cve/nuisance/fix_checks").glob("*.py")):
            print("code", path.name, *code_digest(path))

asyncio.run(main())
```

#### Fix 1.1: `tests/unit/support/audited_launch_builders.py` (test-placement, refactoring)

Problem: tests/unit/support/audited_launch_builders.py is a shared support module. It is imported by tests/unit/cve/test_cve_launches.py, tests/unit/cve/backends/test_audited_launch_names.py and tests/integration/committed/detection/test_detection_holdout_targets.py, and it imports five modules from one area's support directory: tests/unit/cve/backends/support/backend_launch_specs, doris_launch, fake_ckan, fake_control_planes and fake_searxng. The split now differs by fake, with no reason behind it.

Also covers: `tests/unit/cve/backends/support/backend_launch_specs.py` (test-placement): backend_launch_specs lives in the backends area's support, but the shared module tests/unit/support/audited_launch_builders.py imports it (line 17, using a_spec_with_a_holder at :125 and :135). import ast
```python
import pathlib

MOVED: dict[str, set[str]] = {}  # old module -> names that left it, set per step

for path in sorted([*pathlib.Path("evals").rglob("*.py"), *pathlib.Path("tests").rglob("*.py")]):
    tree = ast.parse(path.read_text())
    aliases = {}
    for node in ast.walk(tree):
        if isinstance(node, ast.ImportFrom) and node.module in MOVED:
            for name in node.names:
                if name.name in MOVED[node.module]:
                    print(f"{path}:{node.lineno}: from {node.module} import {name.name}")
        if isinstance(node, ast.Import):
            aliases |= {a.asname or a.name: a.name for a in node.names if a.name in MOVED}
        if isinstance(node, ast.ImportFrom) and node.module:
            aliases |= {
                a.asname or a.name: f"{node.module}.{a.name}"
                for a in node.names
                if f"{node.module}.{a.name}" in MOVED
            }
    for node in ast.walk(tree):
        if isinstance(node, ast.Attribute) and isinstance(node.value, ast.Name) and node.value.id in aliases:
            if node.attr in MOVED[aliases[node.value.id]]:
                print(f"{path}:{node.lineno}: {aliases[node.value.id]}.{node.attr}")
```
