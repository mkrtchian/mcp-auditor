- 2026-10-15: version 6 of the rule. The layout check's reference arm becomes a minimal valid empty node at each layout path, by the node's type (an empty directory, an empty initialised repository, an empty bare repository), in place of a bare empty directory at each path. The reason is a design flaw in the control: an empty directory kills a server that requires its scope to be a valid repository before `tools/list` (`mcp-server-git` validates `--repository` at startup and exits), so that server's reference arm never starts, the break criterion can never be met, and the break detector is structurally blind on it. The arm stays defined by node type, the same for every target, not by server type, so it is not the layout-by-server-type that ADR 031 rejected. The change can only make a target fail a break check, never let one pass, so it goes with the freeze's severity (never changed to make a target pass). The layout check now runs on both versions, and a break on either is a break. No place moves and `evals/holdout_places.json` is unchanged, so the two frozen layout-place fragments regenerated for version 5 stand byte-identical in version 6, their headers unmoved. The excluded servers, dropped target and cutoff of version 1 hold. No holdout target is drawn, so no target changes. The rule is pinned by commit, not by a hash of the file, so no hash is computed. Commit `42ccf1c`.
