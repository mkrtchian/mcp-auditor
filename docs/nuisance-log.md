# Nuisance suite log

This log records the changes to the nuisance suite and the other events its [rule](nuisance-rule.md) says are logged. Each entry is one dated line that names its reason and, once committed, its commit.

- 2026-10-22: version 1 of the rule, opened by ADR 033. On the patched version of each server, the suite counts the cases and chains judged FAIL that call a tool which carried a fixed flaw, in a category valid for that flaw's class. It publishes the share of servers flagged in one run, averaged over its runs, as an "at most" with a Wilson interval over the servers. It also reports the figure of each side of the cutoff of its models. The unit is the server, built at the first release that fixes all of its census flaws that are in a graded class, reached through `tools/call` whatever transport the census records for the flaw, whose effect shows in a tool response and whose vulnerable version is pinnable. The counted flaws are these flaws. A server that does not run over stdio leaves the figure. The patched version of a flaw comes from the advisory's first patched version, then from the first release containing the linked fix commit. A flaw with neither, or none that the fix check clears, is never fixed, and its server leaves the figure. Servers enter in the holdout's salted draw order, at least as far as the holdout walk has gone, each with its census flaws. An addition past the flaws the holdout walk has reached is logged with the number of servers it takes. Two independent agents blind to the auditor admit each server the walk lets in, and decide the class and the patched version of each of its flaws. The maintainer settles their disagreements. Each fix is verified by reproduction: an exploit surfaces a planted witness on the vulnerable version and no longer on the patched one, the benign call working there, which also confirms the chosen version. A benign call on every counted tool must return without error before each run. A tool that needs a backend the container cannot provide, or whose declared function is the effect of its flaw's class, is not counted, and a server with no counted tool left leaves the figure. The traces of the acceptance servers may be read, so none counts in the figure. Those with a current target are audited by a gate run of their own, never by a nuisance run. Every other server is report-only under the reading discipline of the holdout rule. The runs take the chain settings, the tool call timeout and the cutoffs of `evals/holdout_conditions.json`, and the budget of the holdout run they are read beside, with a number of runs a later entry of this log sets. No run has taken place yet. Commit `137fca4`.
- 2026-10-22: the `walk` command over the holdout walk's 86 flaws. `evals/nuisance_walk.py` groups the flaws by server, keeps a server when at least one of its census flaws sets its version (graded class, reached through tools, effect visible in a tool response, pinnable), and marks the excluded and acceptance ones, and `python -m evals.run_nuisance walk` prints the population for the maintainer to admit, no LLM and no network. The living docs (CLAUDE.md, CONTRIBUTING.md, CHANGELOG.md) name the command. No server is admitted, so no figure is produced. Commit `6bf170e`.
- 2026-10-22: the admission file schema. `evals/nuisance_admission.py` holds the pydantic records the admission session fills (the per-server and per-flaw records, the two agents' agreement and the maintainer's settlements) with load checks on the grammar fingerprint, the unsettled disagreements, the foreign flaws, an empty counted set and the patched-version consistency, and `evals/nuisance_counting.py` derives the counted flaws and the counted tools with their valid judge categories from the grammar. The server's patched version is a settled field (`AdmittedServer.patched_version`), not ordered in code, since npm semver and PEP 440 order pre-releases differently and no version library is a dependency. No server is admitted, so no figure is produced. Commit `0cb80e9`.
- 2026-10-22: the fix-check driver in the kit and its fixtures. The no-LLM fix check the admission agent runs until a flaw reproduces lives in the kit tree (`evals/holdout_kit/fix_check.py`) so the exported dossier carries it, planting the flaw's own witness at its coordinate and reproducing it on the vulnerable version, the flaw's patched version and, when it differs, the server's patched version, reusing the clean grammar unchanged. `evals/nuisance_fixtures.py` holds an empty tuple of targets until the admission session. No server is admitted, so no figure is produced. Commit `8ba2b75`.
- 2026-10-22: the `nuisance-dossier` command and its isolation test. `python -m evals.run_nuisance nuisance-dossier` assembles, outside the repository, the self-contained, `mcp_auditor`-free admission dossier for one server (its census flaws' advisories, the fixture format, the grammar classes, the fix-check driver and a kit tree) for the two blind admission agents, with an import-closure test pinning that the written tree imports nothing from `mcp_auditor`. The living docs (CLAUDE.md, CONTRIBUTING.md, CHANGELOG.md) name the command. No server is admitted, so no figure is produced. Commit `26fbb1f`.
- 2026-10-22: the patched-image namespace, the injected tag and the admitted server's fixture fingerprint. `evals/nuisance_images.py` carries the nuisance image tag and the acceptance-namespace guard wired into the admission load checks, and `cve_images` takes an injectable tag so the nuisance suite reads its own image namespace. No server is admitted, so no figure is produced. Commit `d705072`.
