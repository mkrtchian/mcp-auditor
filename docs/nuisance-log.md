# Nuisance suite log

This log records the changes to the nuisance suite and the other events its [rule](nuisance-rule.md) says are logged. Each entry is one dated line that names its reason and, once committed, its commit.

- 2026-10-22: version 1 of the rule, opened by ADR 033. On the patched version of each server, the suite counts the cases and chains judged FAIL that call a tool which carried a fixed flaw, in a category valid for that flaw's class. It publishes the share of servers flagged in one run, averaged over its runs, as an "at most" with a Wilson interval over the servers. It also reports the figure of each side of the cutoff of its models. The unit is the server, built at the first release that fixes all of its census flaws that are in a graded class, reached through `tools/call` whatever transport the census records for the flaw, whose effect shows in a tool response and whose vulnerable version is pinnable. The counted flaws are these flaws. A server that does not run over stdio leaves the figure. The patched version of a flaw comes from the advisory's first patched version, then from the first release containing the linked fix commit. A flaw with neither, or none that the fix check clears, is never fixed, and its server leaves the figure. Servers enter in the holdout's salted draw order, at least as far as the holdout walk has gone, each with its census flaws. An addition past the flaws the holdout walk has reached is logged with the number of servers it takes. Two independent agents blind to the auditor admit each server the walk lets in, and decide the class and the patched version of each of its flaws. The maintainer settles their disagreements. Each fix is verified by reproduction: an exploit surfaces a planted witness on the vulnerable version and no longer on the patched one, the benign call working there, which also confirms the chosen version. A benign call on every counted tool must return without error before each run. A tool that needs a backend the container cannot provide, or whose declared function is the effect of its flaw's class, is not counted, and a server with no counted tool left leaves the figure. The traces of the acceptance servers may be read, so none counts in the figure. Those with a current target are audited by a gate run of their own, never by a nuisance run. Every other server is report-only under the reading discipline of the holdout rule. The runs take the chain settings, the tool call timeout and the cutoffs of `evals/holdout_conditions.json`, and the budget of the holdout run they are read beside, with a number of runs a later entry of this log sets.
